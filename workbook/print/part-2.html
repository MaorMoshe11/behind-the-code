איך הרשת עובדת

מה קורה בין הרגע שתוכנית שולחת בקשה לבין הרגע שמגיעה תשובה, ואיך רואים את זה בעיניים, על המחשב שלכם, בלי אינטרנט.

בסוף הפרק תדעו

  • להסביר מה קורה בין הקלדת כתובת לבין קבלת תשובה: DNS, חיבור ל-port, TLS, ובקשת HTTP.
  • להריץ שרת קטן על המחשב שלכם ולשלוח אליו בקשות עם curl.exe, ואפילו ביד, כטקסט.
  • לקרוא בקשה ותשובה: method, path, headers, body ב-JSON, ו-status code.
  • לראות מה ה-SDK של Anthropic באמת שולח, ואיך הוא מגיב לכל סוג של שגיאה.
  • לזהות באיזה שלב בקשה נכשלה, לפי הודעת השגיאה בלבד.

זמן משוער: שלוש עד ארבע שעות, כולל התרגילים. מה צריך: הפרויקט מסוף פרק 3. אין צורך באינטרנט ולא במפתח: כל השרתים בפרק רצים אצלכם.

4.1הבעיה: שלוש שגיאות, הודעה אחת

בסוף פרק 3 גרמתם לסוכן להיכשל בכוונה, והסתכלתם ב-agent.log. היו שם דברים שלא הסברנו: הכתובת http://127.0.0.1:9, השגיאה WinError 10061, והשורה "Retrying request to /v1/messages". עבדתם עם ה-API שלושה פרקים, ועוד לא ראיתם אף בקשה אחת שיצאה ממנו.

וזה לא רק סקרנות. נניח שמשתמש כותב לכם: "הסוכן אומר Could not reach the API". ההודעה הזו מכסה לפחות שלוש תקלות שונות לגמרי. אולי שם השרת לא מתורגם לכתובת (בעיית DNS, למשל רשת ארגונית). אולי הכתובת נכונה אבל אף אחד לא עונה בה (firewall, או proxy). ואם השרת כן ענה, אבל בשגיאה, הודעה אחרת לגמרי הייתה מופיעה. לכל אחת מהן תיקון אחר, ומי שלא מבין את השלבים מנחש.

הפרק עובר על השלבים האלה אחד אחד. בסופו תריצו שרת משלכם, תפנו אליו את הסוכן, ותראו את הבקשה המלאה שה-SDK שולח, כולל כל שורה בה. ובפרק 5, כשתבנו API משלכם, תהיו בצד השני של אותה שיחה.

4.2המפה: ארבעה שלבים של בקשה אחת

כשהסוכן קורא ל-messages.create, ה-SDK צריך להגיע ל-https://api.anthropic.com/v1/messages. ה-URL הזה מכיל את כל מה שצריך כדי לעשות את זה:

חלקבדוגמהמה הוא אומר
schemehttpsבאיזה פרוטוקול לדבר. https הוא HTTP מוצפן, http בלי הצפנה
hostapi.anthropic.comשם השרת. צריך לתרגם אותו לכתובת מספרית
portלא כתוב, ולכן 443איזו "דלת" בשרת. ל-https ברירת המחדל היא 443, ל-http היא 80
path/v1/messagesמה מבקשים מהשרת. כאן: גרסה 1 של ה-API, משאב ההודעות

ומכאן ארבעה שלבים, תמיד באותו סדר:

1. DNS
מתרגמים את השם לכתובת IP: api.anthropic.com הוא, למשל, 160.79.104.10
→
2. TCP connect
פותחים חיבור לכתובת, ל-port 443. מישהו צריך להאזין שם
→
3. TLS
מוודאים שזה באמת השרת הנכון, ומצפינים את החיבור. רק ב-https
→
4. HTTP
שולחים בקשה (טקסט), ומקבלים תשובה עם status code
כל שלב יכול להיכשל, וכל כישלון נראה אחרת. אם שלב נכשל, השלבים שאחריו לא קורים בכלל.

הצד ששולח בקשה נקרא client, והצד שמאזין ועונה נקרא server. אלה תפקידים, לא סוגי מחשבים: הסוכן שלכם הוא client של Anthropic, ובפרק 5 הוא יהיה גם server, שדפדפן פונה אליו. נתחיל מהסוף, משלב 4, כי אותו אפשר לראות הכי טוב. בשביל זה צריך שרת.

4.3שרת משלכם: כתובות, ports ו-localhost

ל-Python יש שרת מובנה, http.server, שמגיש את הקבצים שבתיקייה. הוא לא מיועד לייצור, אבל הוא מושלם לניסויים. צרו תיקייה נפרדת, ~\projects\net-lab, ובה קובץ index.html (ב-VS Code) עם שורה אחת: <h1>Hello from my own server</h1>. ואז:

PowerShell
cd ~\projects\net-lab
uv run python -m http.server 8000 --bind 127.0.0.1
output
Serving HTTP on 127.0.0.1 port 8000 (http://127.0.0.1:8000/) ...

ה-terminal "נתקע", וזה בסדר: שרת הוא תוכנית שלא נגמרת, היא מחכה לבקשות. עצירה היא Ctrl+C. פתחו בדפדפן http://localhost:8000 ותראו את הכותרת. ב-terminal של השרת הופיעה שורה על כל בקשה, זה ה-access log שלו:

output
127.0.0.1 - - [18/Nov/2026 13:17:54] "GET / HTTP/1.1" 200 -
לעולם לא בתיקיית הפרויקט

http.server מגיש כל קובץ בתיקייה שבה הפעלתם אותו. מתוך my-agent, כל מי שמגיע לשרת יכול לבקש את /.env ולקבל את המפתח שלכם. לכן net-lab נפרדת, ולכן --bind 127.0.0.1, שמוסבר מיד.

כתובת ו-port

לכל מחשב ברשת יש כתובת IP, כמו 160.79.104.10 (IPv4), או הארוכה יותר 2001:db8::10 (IPv6). כתובת אחת מספיקה כדי להגיע למחשב, אבל על המחשב רצות הרבה תוכניות. ה-port, מספר בין 1 ל-65535, אומר לאיזו מהן. תוכנית ש"מאזינה על port 8000" מקבלת את כל החיבורים שמגיעים למספר הזה. זה מה ש-Serving HTTP on 127.0.0.1 port 8000 אומר.

למה 8000? מספרים מתחת ל-1024 שמורים לשירותים מוכרים (80 ל-http, 443 ל-https), ו-8000 הוא ברירת המחדל של http.server וגם של השרת שתבנו בפרק 5. אין בו קסם: כל מספר פנוי מעל 1024 עובד. אם 8000 תפוס אצלכם, בחרו 8001, ושנו בהתאם בכל הפקודות.

localhost, 127.0.0.1 ו---bind

127.0.0.1 היא כתובת מיוחדת: "המחשב הזה". בקשה אליה לא יוצאת לרשת בכלל, ולכן כל הפרק עובד בלי אינטרנט. localhost הוא שם שמתורגם אליה, ותראו בסעיף 4.6 שגם ל-::1, הגרסה של IPv6. שימו לב לפרט הזה, הוא יחזור.

--bind 127.0.0.1 אומר לשרת להאזין רק על הכתובת הזו, כלומר רק לתוכניות במחשב שלכם. בלי הדגל, http.server מאזין על כל הכתובות של המחשב, ומי שמחובר לאותה רשת (בבית קפה, במשרד) יכול להגיע אליו. Windows גם עשוי לקפוץ עם חלון של Windows Defender Firewall ששואל אם לאפשר. כשאתם מפתחים, הכלל הוא להאזין על 127.0.0.1, אלא אם יש סיבה טובה אחרת.

4.4curl.exe, ומלכודת ה-alias

דפדפן מציג את התשובה, ומסתיר את כל השאר. הכלי שמראה הכול הוא curl, שמגיע עם Windows 10 ו-11. פתחו terminal שני (השרת ממשיך לרוץ בראשון. ב-VS Code: הכפתור Split Terminal), ונסו:

PowerShell
curl -i http://127.0.0.1:8000/
output (shortened)
Invoke-WebRequest : Cannot process command because of one or more missing mandatory parameters: Uri.

השגיאה מגיעה מ-Invoke-WebRequest, לא מ-curl. ב-PowerShell 5.1, שמגיע עם Windows, curl הוא alias, כינוי, לפקודה של PowerShell עצמו, עם פרמטרים אחרים לגמרי. -i פורש אצלו כפרמטר אחר, וה-URL "נבלע". בלי דגלים הוא כן רץ, אבל עשוי לעצור ולשאול שאלת אבטחה על הרצת סקריפטים מהדף, ובשגיאות HTTP הוא זורק חריגה במקום להראות את התשובה. בדקו בעצמכם:

PowerShell
Get-Command curl          # CommandType: Alias, Definition: Invoke-WebRequest
Get-Command curl.exe      # C:\Windows\system32\curl.exe, the real curl

הכלל לכל החוברת: תמיד curl.exe, עם הסיומת. כך PowerShell מריץ את התוכנה האמיתית, וכל דוגמה של curl שתמצאו באינטרנט תעבוד אצלכם (כמעט, ראו תרגיל 5).

PowerShell
curl.exe -i http://127.0.0.1:8000/
output
HTTP/1.0 200 OK
Server: SimpleHTTP/0.6 Python/3.12.13
Date: Wed, 18 Nov 2026 11:17:54 GMT
Content-type: text/html
Content-Length: 34
Last-Modified: Wed, 18 Nov 2026 11:17:50 GMT

<h1>Hello from my own server</h1>

הדגל -i מוסיף לפלט את מה שהדפדפן הסתיר: שורת הסטטוס ואת ה-headers. אצלכם המספר ב-Content-Length עשוי להיות שונה בבית אחד, לפי סוג סוף השורה שנשמר בקובץ. ה-Date הוא תמיד בשעון גריניץ' (GMT), ולכן הוא לא תואם את השעה במחשב שלכם.

4.5HTTP: בקשה ותשובה

הנה הסוד הגדול של HTTP: הוא טקסט. בקשה היא כמה שורות שהלקוח כותב לחיבור, ותשובה היא כמה שורות שהשרת כותב בחזרה. כדי להוכיח את זה תשלחו בקשה בלי שום ספרייה של HTTP, רק חיבור ומחרוזת. זה הקובץ הראשון בתיקייה חדשה, scripts, ולכן קודם ענף:

PowerShell
cd ~\projects\my-agent
git switch main
git pull
git switch -c feature/network-scripts
mkdir scripts
scripts\raw_http.py
"""Send one HTTP request by hand, as plain text over a TCP connection.

Run it with: uv run python scripts/raw_http.py 127.0.0.1 8000
"""

import socket
import sys

# The whole request. Every line ends with \r\n.
REQUEST = (
    "GET / HTTP/1.1\r\n"  # the request line: method, path, protocol version
    "Host: 127.0.0.1\r\n"  # headers, one per line
    "Connection: close\r\n"
    "\r\n"  # an empty line: the headers are over (a GET has no body)
)


def main() -> None:
    host, port = sys.argv[1], int(sys.argv[2])
    with socket.create_connection((host, port), timeout=5) as connection:
        connection.sendall(REQUEST.encode("ascii"))
        reply = b""
        while chunk := connection.recv(4096):  # read until the server closes
            reply += chunk
    print(reply.decode("utf-8", errors="replace"))


if __name__ == "__main__":
    main()

socket.create_connection הוא שלבים 1 ו-2 מהמפה: הוא מתרגם את השם לכתובת ופותח חיבור TCP. TCP הוא הצינור שמתחת ל-HTTP: הוא דואג שהבתים יגיעו, בסדר הנכון ובלי חורים, ולא אכפת לו מה כתוב בהם. מה שכתוב בהם הוא HTTP, והוא כולו במחרוזת REQUEST. הריצו:

PowerShell
uv run python scripts\raw_http.py 127.0.0.1 8000

תקבלו בדיוק את מה ש-curl.exe -i הראה. ה-terminal של השרת רשם בקשה נוספת. שמרו: git add scripts ואז git commit -m "Send an HTTP request by hand with raw_http.py".

Methods: מה רוצים לעשות

ה-method הוא הפועל של הבקשה. יש כמה, וחמישה מכסים כמעט הכול:

העמודה האחרונה נקראת idempotency, והיא חשובה כשבקשה נכשלת באמצע: מותר לנסות שוב רק אם ניסיון נוסף לא יזיק. תראו את ה-SDK מחליט את זה בתרגיל 4, ותחזרו לזה ברצינות בפרק 11.

Status codes: מה קרה

המספר בשורה הראשונה של התשובה. הספרה הראשונה אומרת את רוב מה שצריך לדעת: 2xx הצליח, 3xx חפשו במקום אחר, 4xx הבעיה בבקשה שלכם, 5xx הבעיה בשרת. ההבדל בין 4 ל-5 הוא ההבדל בין "תקנו משהו אצלכם" לבין "נסו שוב אחר כך".

Headers ו-JSON

ה-headers הם מידע על הבקשה או התשובה. שמות שלא משנה אם כותבים באותיות גדולות או קטנות (Content-type ו-Content-Type זהים), וכמה שתפגשו כל יום:

Headerמה הוא אומר
Hostלאיזה אתר הבקשה. שרת אחד יכול לשרת הרבה שמות
Content-Typeאיך לקרוא את ה-body: text/html, application/json
Content-Lengthכמה בתים יש ב-body, כדי שהצד השני יידע מתי הוא נגמר
Authorizationמי אתם: מפתח או token. סוד, בדיוק כמו המפתח עצמו
User-Agentאיזו תוכנה שולחת: דפדפן, curl, ה-SDK

וה-body? כששתי תוכניות מחליפות נתונים, ולא דף לאדם, הן כמעט תמיד משתמשות ב-JSON: טקסט שנראה כמו dict ו-list של Python, עם מירכאות כפולות בלבד, true, false ו-null. ב-Python, json.dumps הופך אובייקט לטקסט, ו-json.loads הופך טקסט בחזרה. ה-SDK עושה את שני הכיוונים בשבילכם, ובסעיף 4.8 תראו את הטקסט עצמו.

4.6DNS, ושלוש דרכים להיכשל

שלב 1 במפה. אף אחד לא זוכר 160.79.104.10, ולכן משתמשים בשמות. DNS (Domain Name System) הוא מערכת עולמית של שרתים שעונים על שאלה אחת: לאיזו כתובת שייך השם הזה. המחשב שלכם שואל שרת DNS (בדרך כלל של הנתב או של ספק האינטרנט), שומר את התשובה לזמן מה, ורק אז פותח חיבור. את localhost Windows יודע לבד, בלי לשאול אף אחד:

PowerShell
Resolve-DnsName localhost
output
Name                                           Type   TTL   Section    IPAddress
----                                           ----   ---   -------    ---------
localhost                                      AAAA   1200  Question   ::1
localhost                                      A      1200  Question   127.0.0.1

שתי תשובות: AAAA היא כתובת IPv6, ו-A היא IPv4. אם יש לכם אינטרנט, נסו גם Resolve-DnsName api.anthropic.com. התשובה אצלכם עשויה להיות שונה מזו שבמפה: לשירותים גדולים יש הרבה כתובות, והן משתנות. זו בדיוק הסיבה שמשתמשים בשמות.

4.7HTTPS ו-TLS, במבט מלמעלה

כל מה שראיתם עד עכשיו עבר כטקסט גלוי. זה בסדר בתוך המחשב שלכם, אבל בדרך ל-api.anthropic.com הבקשה עוברת דרך הנתב, ספק האינטרנט ועוד כמה מחשבים בדרך. כל אחד מהם היה יכול לקרוא את המפתח שלכם מתוך Authorization, או לשנות את התשובה.

TLS (Transport Layer Security) הוא שלב 3, והוא פותר שלוש בעיות. הצפנה: רק שני הקצוות יכולים לקרוא. שלמות: שינוי בדרך מתגלה. זהות: השרת מציג תעודה (certificate) שגוף מוכר חתם עליה, ובה כתוב "אני api.anthropic.com". הלקוח בודק את החתימה ואת השם, ואם משהו לא מתאים, הוא מסרב להמשיך. HTTPS הוא פשוט HTTP בתוך TLS: אותן שורות בדיוק, בתוך צינור מוצפן.

שתי מסקנות מעשיות. ראשית, מפתח נשלח רק ב-https. היום תשלחו מפתח מזויף ב-http, וזה בסדר רק כי הוא מזויף והבקשה לא עוזבת את המחשב. שנית, אי אפשר לראות את הבקשות האמיתיות של הסוכן מבחוץ, וזה בדיוק העניין. כדי לראות מה ה-SDK שולח, לא מצותתים לחיבור. מפנים את ה-SDK לשרת שלכם.

2שרת שמדפיס בקשות

http.server בנוי משני חלקים: HTTPServer, שמאזין ומקבל חיבורים, ו-handler, מחלקה שמקבלת כל בקשה ומחליטה מה לענות. http.server הריץ handler שמגיש קבצים. אתם כותבים handler משלכם. צרו את scripts\echo_server.py:

scripts\echo_server.py
"""A tiny local HTTP server that prints every request it receives.

Point the agent at it to see exactly what the Anthropic SDK sends:

    uv run python scripts/echo_server.py
    $env:ANTHROPIC_BASE_URL = "http://127.0.0.1:8000"

POST /v1/messages gets a fake reply in the shape of the Messages API, so the
real ClaudeClient works against this server: offline, free, no real key needed.
"""

import argparse
import json
from http.server import BaseHTTPRequestHandler, HTTPServer

# Headers that carry secrets: print only their first characters.
SECRET_HEADERS = {"authorization", "x-api-key"}


def hide_secret(value: str) -> str:
    """'Bearer sk-ant-abc123' -> 'Bearer sk-a***'."""
    scheme, _, token = value.rpartition(" ")
    return f"{scheme} {token[:4]}***".strip()


def fake_message(request: dict[str, object]) -> dict[str, object]:
    """A reply shaped like the Messages API's, so the SDK can read it."""
    messages = request.get("messages", [])
    count = len(messages) if isinstance(messages, list) else 0
    return {
        "id": "msg_echo",
        "type": "message",
        "role": "assistant",
        "model": request.get("model", "unknown"),
        "content": [{"type": "text", "text": f"[echo server] messages received: {count}"}],
        "stop_reason": "end_turn",
        "stop_sequence": None,
        "usage": {"input_tokens": 0, "output_tokens": 0},  # fake counts
    }


class EchoHandler(BaseHTTPRequestHandler):
    """Called by HTTPServer once for every request that arrives."""

    def do_GET(self) -> None:
        self.answer()

    def do_POST(self) -> None:
        self.answer()

    def answer(self) -> None:
        length = int(self.headers.get("Content-Length", "0"))
        body = self.rfile.read(length)
        self.print_request(body)

        if self.command == "POST" and self.path == "/v1/messages":
            self.send_json(200, fake_message(json.loads(body)))
        else:
            self.send_json(200, {"method": self.command, "path": self.path, "bytes": length})

    def print_request(self, body: bytes) -> None:
        print(f"\n--- {self.requestline}")
        for name, value in self.headers.items():
            if name.lower() in SECRET_HEADERS:
                value = hide_secret(value)
            print(f"{name}: {value}")
        if body:
            print()
            print(body.decode("utf-8"))

    def send_json(self, status: int, data: dict[str, object]) -> None:
        payload = json.dumps(data).encode("utf-8")
        self.send_response(status)
        self.send_header("Content-Type", "application/json")
        self.send_header("Content-Length", str(len(payload)))
        self.end_headers()
        self.wfile.write(payload)


def main() -> None:
    parser = argparse.ArgumentParser(description="Print every HTTP request it receives.")
    parser.add_argument("--port", type=int, default=8000)
    args = parser.parse_args()

    # 127.0.0.1: only programs on this computer can connect, not the network.
    server = HTTPServer(("127.0.0.1", args.port), EchoHandler)
    print(f"Echo server on http://127.0.0.1:{args.port} (Ctrl+C to stop)")
    try:
        server.serve_forever()
    except KeyboardInterrupt:
        print("\nStopped.")


if __name__ == "__main__":
    main()

שלושה דברים לשים לב אליהם. השרת קורא בדיוק Content-Length בתים, כי אחרת אין לו דרך לדעת איפה ה-body נגמר. כל תשובה שלו נבנית מאותם שלושה חלקים: שורת סטטוס (send_response), headers, ו-body. ומפתחות לא מודפסים במלואם, גם לא במחשב שלכם (פרק 3, סעיף 3.9).

5.3מה זה API, ומה זה REST

API הוא חוזה: לאיזו כתובת שולחים, מה שולחים, ומה מקבלים בחזרה, כולל מה קורה כשמשהו לא בסדר. מי שקורא ל-API שלכם לא רואה את הקוד שלכם, ולא אמור לראות. הוא סומך על החוזה. לכן הכלל הראשון: מותר לשנות כל דבר מאחורי החוזה, ואסור לשבור את החוזה עצמו בלי להודיע. שדה שנעלם מתשובה שובר את כל מי שקרא אותו.

REST הוא הסגנון הנפוץ לחוזים כאלה מעל HTTP. הוא לא תקן עם חוקים מדויקים, אלא כמה הרגלים:

  • ה-URL הוא שם עצם, משאב (resource): /conversations/42, ולא /getConversation?id=42.
  • ה-method הוא הפועל: GET קורא, POST יוצר או שולח, DELETE מוחק (הטבלה מסעיף 4.5).
  • ה-status code אומר מה קרה, וה-body ב-JSON מוסיף פרטים.
  • כל בקשה עומדת בפני עצמה (stateless): השרת לא זוכר "מי דיבר איתי קודם". מה שצריך, הבקשה מביאה איתה.

הנקודה האחרונה חשובה לסוכן. ב-terminal יש שיחה אחת, והיא חיה במשתנה. בשרת מדברים איתו הרבה לקוחות בבת אחת, ולכן לכל שיחה יש מזהה (conversation_id), והלקוח שולח אותו בכל הודעה. זה החוזה שתבנו:

"""The core of the agent: conversations and their messages.

The terminal chat and the HTTP API both use this module, so they behave the same.
Everything lives in memory: when the process stops, every conversation is gone.
"""

import logging
import uuid

from anthropic.types import MessageParam

from agent.history import trim_history
from agent.llm import ChatClient, LLMError

log = logging.getLogger(__name__)


class ConversationNotFound(Exception):
    """No conversation has this id (maybe the server restarted)."""


class Conversations:
    """Every open conversation, by id, and the one way to add a message to it."""

    def __init__(self, client: ChatClient, max_turns: int) -> None:
        self.client = client
        self.max_turns = max_turns
        self._messages: dict[str, list[MessageParam]] = {}

    def start(self) -> str:
        """Open a new, empty conversation and return its id."""
        conversation_id = uuid.uuid4().hex
        self._messages[conversation_id] = []
        return conversation_id

    def messages(self, conversation_id: str) -> list[MessageParam]:
        """The messages the agent still remembers in this conversation."""
        if conversation_id not in self._messages:
            raise ConversationNotFound(conversation_id)
        return self._messages[conversation_id]

    def send(self, conversation_id: str, text: str) -> str:
        """Add the user's message, get the model's reply, and remember both."""
        messages = self.messages(conversation_id)
        messages.append({"role": "user", "content": text})
        log.info("sending %d messages", len(messages))
        try:
            reply = self.client.reply(messages)
        except LLMError:
            messages.pop()  # forget the message that got no answer
            raise
        messages.append({"role": "assistant", "content": reply})
        # Keep only the last turns, so long chats do not get slow and expensive.
        self._messages[conversation_id] = trim_history(messages, self.max_turns)
        return reply

    def reset(self, conversation_id: str) -> None:
        """Forget every message in this conversation, but keep the conversation."""
        self.messages(conversation_id).clear()

5.6Schemas עם Pydantic: POST /chat

ב-echo_server.py קראתם את ה-body עם json.loads וקיוויתם לטוב. מה אם חסר שדה? מה אם message הוא מספר? כל endpoint היה צריך לבדוק את זה ביד. ב-FastAPI מתארים את הצורה פעם אחת, כ-schema: מחלקה של Pydantic, עם type hints מפרק 3. החליפו את api.py בגרסה הזו:

agent\api.py
"""The agent as an HTTP service.

Run it with: uv run uvicorn agent.api:create_app --factory
"""

import logging

from dotenv import load_dotenv
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, Field

from agent.cli import setup_logging
from agent.config import SYSTEM_PROMPT, ConfigError, Settings, load_settings
from agent.conversations import ConversationNotFound, Conversations
from agent.llm import ChatClient, ClaudeClient, LLMError, MockClient

log = logging.getLogger(__name__)


class ChatRequest(BaseModel):
    """What a client sends to POST /chat."""

    message: str = Field(min_length=1, max_length=4000)
    conversation_id: str | None = Field(
        default=None, description="Leave it out to start a new conversation."
    )


class ChatResponse(BaseModel):
    """What POST /chat sends back."""

    conversation_id: str
    reply: str
    turns: int = Field(description="How many turns the agent remembers in this conversation.")


def make_client(settings: Settings) -> ChatClient:
    """The mock or the real client. A server cannot ask questions, so it refuses to start."""
    if settings.mock:
        return MockClient()
    if not settings.api_key:
        raise ConfigError("ANTHROPIC_API_KEY is not set (or set CHAT_MOCK=1).")
    return ClaudeClient(settings.model, SYSTEM_PROMPT)


def create_app(settings: Settings | None = None, client: ChatClient | None = None) -> FastAPI:
    """Build the app. uvicorn calls it with nothing; tests pass their own settings and client."""
    if settings is None:
        load_dotenv()
        settings = load_settings()
        setup_logging(settings.log_level)
    conversations = Conversations(client or make_client(settings), settings.max_turns)
    app = FastAPI(title="my-agent", version="0.5.0")

    @app.get("/health")
    def health() -> dict[str, str]:
        """Is the service up? Used by people and by monitoring."""
        return {"status": "ok"}

    @app.post("/chat")
    def chat(request: ChatRequest) -> ChatResponse:
        """Send one message. The reply comes back with the conversation's id."""
        conversation_id = request.conversation_id or conversations.start()
        try:
            reply = conversations.send(conversation_id, request.message)
        except ConversationNotFound:
            raise HTTPException(status_code=404, detail="No conversation with this id.") from None
        except LLMError as error:
            log.exception("request failed")
            raise HTTPException(status_code=502, detail=str(error)) from error
        turns = len(conversations.messages(conversation_id)) // 2
        return ChatResponse(conversation_id=conversation_id, reply=reply, turns=turns)

    return app

השורה המסומנת האחרונה עושה שלושה דברים. הפרמטר request: ChatRequest אומר ל-FastAPI: קרא את ה-body כ-JSON, ובדוק שהוא מתאים ל-ChatRequest. אם לא, הפונקציה לא נקראת בכלל, והלקוח מקבל 422 עם פירוט. וה--> ChatResponse אומר מה יוצא: FastAPI מוודא שהתשובה בצורה הזו, ולא שולח שדות שלא הוגדרו בה. החריגות של הליבה הופכות ל-status codes מהחוזה, וזה כל מה ש-api.py עושה: מתרגם בין HTTP לבין הליבה.

שני דברים נוספים. make_client לא שואל ולא מדפיס כמו בגרסה של ה-CLI: לשרת אין מי שיענה, ולכן הגדרה חסרה עוצרת אותו מיד, בעלייה, ולא בבקשה הראשונה של לקוח. ו-def chat היא פונקציה רגילה ולא async: FastAPI מריץ אותה ב-thread נפרד, כך ששאלה איטית ל-Claude לא תוקעת את כל שאר הלקוחות.

5.8אימות: מי מדבר איתי?

ברגע שהשרת מדבר עם Claude אמיתי, כל בקשה עולה לכם כסף. כרגע כל מי שמגיע ל-port יכול לשלוח בקשות. אימות (authentication) הוא התשובה לשאלה "מי אתה", והרשאה (authorization) לשאלה "מה מותר לך". בפרק 4 ראיתם את שתיהן בקודים: 401 לא ברור מי אתם, 403 ברור, ואסור.

api_key_header = APIKeyHeader(name="X-API-Key", auto_error=False)


def key_checker(expected: str) -> Callable[[str | None], None]:
    """Build the dependency that guards an endpoint: no key, or a wrong key, gets 401."""

    def check(key: Annotated[str | None, Depends(api_key_header)]) -> None:
        # compare_digest takes the same time for every wrong key, so timing reveals nothing.
        if key is None or not secrets.compare_digest(key, expected):
            raise HTTPException(status_code=401, detail="Missing or wrong X-API-Key header.")

    return check

# in create_app, after the settings are loaded:
    if not settings.agent_api_key:
        # Fail closed: a server without a key would let anyone spend your API credit.
        raise ConfigError("AGENT_API_KEY is not set. Put a long random value in .env.")
    conversations = Conversations(client or make_client(settings), settings.max_turns)
    require_key = Depends(key_checker(settings.agent_api_key))
    ...
    @app.post("/chat", dependencies=[require_key])

Webhooks: ה-API שקורא לכם

נניח שהסוכן היה מחכה לאישור תשלום משירות חיצוני. אפשר לשאול אותו כל דקה "נו, אושר?" (polling): בזבזני, ותמיד באיחור. ההפך הוא webhook: נותנים לשירות URL שלכם, והוא שולח אליו POST ברגע שמשהו קורה. כלומר אתם כותבים endpoint, והשירות האחר הוא ה-client. ארבעה דברים שכל מי שמקבל webhooks צריך לדעת:

  • כל אחד יכול לשלוח POST לכתובת שלכם. לכן השולח חותם על ה-body בסוד משותף (HMAC), ושולח את החתימה ב-header. אתם מחשבים אותה מחדש ומשווים, עם hmac.compare_digest, בדיוק כמו המפתח בסעיף 5.8.
  • עונים מהר, עם 2xx. עבודה ארוכה עושים אחר כך (פרק 12). שולח שלא קיבל תשובה בזמן מניח שנכשלתם.
  • אותו אירוע עלול להגיע פעמיים, כי השולח מנסה שוב. לכל אירוע יש מזהה, ומי שכבר טיפל בו מתעלם (idempotency, פרק 11).
  • צריך כתובת שהשולח מגיע אליה. 127.0.0.1 לא מספיק, ולכן webhooks מגיעים לשרתים אמיתיים (פרק 10).

6.3המודל הרלציוני: טבלאות, שורות ומפתחות

בסיס נתונים רלציוני (relational database) שומר הכול בטבלאות. לכל טבלה (table) יש עמודות קבועות (columns), ולכל עמודה type. כל רשומה היא שורה (row). כך ייראו השיחות של הסוכן, בשתי טבלאות:

  • Primary key (PK): עמודה שהערך בה שונה בכל שורה, ולכן מזהה אותה. בשיחות זה ה-conversation_id שכבר נוסע בכל בקשה מפרק 5. בהודעות זה מספר רץ שבסיס הנתונים נותן לבד.
  • Foreign key (FK): עמודה שמצביעה על primary key בטבלה אחרת. messages.conversation_id אומר לאיזו שיחה ההודעה שייכת, ובסיס הנתונים יכול לסרב להודעה של שיחה שלא קיימת.

למה שתי טבלאות, ולא עמודה אחת של "כל ההודעות" בשורה של השיחה? כי כך כל שאלה פשוטה: "ההודעות של c1 לפי הסדר", "כמה הודעות בכל שיחה", "כל ההודעות של היום". הכלל נקרא normalization: כל עובדה נשמרת פעם אחת, במקום אחד, והקשרים נבנים מהמפתחות. ושימו לב שאין כאן קיצוץ: הטבלה שומרת את כל ההודעות, גם אם למודל נשלחות רק האחרונות.

6.4SQL ביד, ב-SQLite

SQL (Structured Query Language) היא השפה שבה מדברים עם כמעט כל בסיס נתונים רלציוני. היא הצהרתית: אתם כותבים מה אתם רוצים, ובסיס הנתונים מחליט איך להשיג את זה. SQLite הוא בסיס הנתונים הפשוט ביותר להתחיל איתו: אין שרת, כל בסיס הנתונים הוא קובץ אחד, והוא מגיע מובנה בתוך Python. גם הכלי להסתכל לתוכו מובנה: python -m sqlite3, מגרסה 3.12. ענף חדש, ודבר ראשון: לוודא שקבצי בסיס נתונים לא ייכנסו ל-git.

CREATE TABLE conversations (
  id TEXT PRIMARY KEY,

);

  id INTEGER PRIMARY KEY,

NOT NULL אומר שאסור לשורה להגיע בלי ערך בעמודה. INTEGER PRIMARY KEY ב-SQLite הוא מספר רץ: לא נותנים ערך, ובסיס הנתונים בוחר את הבא. REFERENCES הופך את conversation_id ל-foreign key. עכשיו נתונים, ושורה אחת שגויה בכוונה:

INSERT INTO conversations (id, created_at) VALUES ('c1', '2026-11-18 12:00');

  ('c1', 'user', 'what is SQL?'),

זה ה-primary key בעבודה: שתי שיחות עם אותו מזהה הן בדיוק הבאג שבסיס הנתונים מונע בשבילכם. מחרוזות ב-SQL נכתבות במירכאות בודדות. ועכשיו שאלות. כל אחת מהן היא SELECT: אילו עמודות, מאיזו טבלה, אילו שורות (WHERE) ובאיזה סדר (ORDER BY):

6.6Transactions: הכול או כלום

כשהסוכן עונה, נוספות שתי שורות: ההודעה שלכם והתשובה. מה אם השרת קורס אחרי הראשונה? בשיחה יש שאלה בלי תשובה, ובפרק 1 ראיתם שה-API של Claude דורש שהתורות יתחלפו. Transaction היא קבוצת פקודות שבסיס הנתונים מבטיח שיקרו כיחידה אחת: או כולן, או אף אחת. נסו:

sqlite>
BEGIN;
DELETE FROM messages;
SELECT COUNT(*) FROM messages;
ROLLBACK;
SELECT COUNT(*) FROM messages;
output
(0,)
(5,)

בתוך ה-transaction הטבלה ריקה. ROLLBACK ביטל הכול, כאילו לא קרה. COMMIT היה הופך את השינוי לקבוע. ה-shell הזה עובד במצב autocommit: כל פקודה מחוץ ל-BEGIN היא transaction קטנה משלה. כתבו .quit כדי לצאת.

מאחורי זה ארבע הבטחות שנקראות יחד ACID: atomicity (הכול או כלום), consistency (חוקים כמו foreign keys נשמרים), isolation (מי שקורא באמצע לא רואה חצי שינוי) ו-durability (מה שעבר COMMIT שורד גם הפסקת חשמל). זה ההבדל העיקרי מקובץ JSON.

לא מחזיקים transaction פתוחה בזמן שמחכים לרשת

שאלה ל-Claude לוקחת שניות. אם transaction פתוחה כל הזמן הזה, היא עלולה לחסום כותבים אחרים: ב-SQLite רק כותב אחד יכול להחזיק את הקובץ בכל רגע. לכן הסוכן יקרא את ההיסטוריה, יסגור, ישאל את המודל, ורק כשהתשובה ביד יכתוב את שתי ההודעות ב-transaction אחת קצרה. ואם המודל נכשל, אין מה לבטל: עוד לא נכתב כלום.

6.7ORM: SQLAlchemy

אפשר לכתוב את כל הסוכן עם SQL במחרוזות ומודול sqlite3. בפרויקט אמיתי זה נהיה מסורבל: להמיר כל שורה למילון ובחזרה, לכתוב CREATE TABLE שמתאים לקוד, ולכתוב SQL קצת שונה לכל בסיס נתונים. למה לא פשוט f-string?

אם הייתם כותבים f"SELECT * FROM messages WHERE conversation_id = '{cid}'", מזהה שמכיל מירכאה היה משנה את משמעות השאלה. משתמש זדוני יכול לשלוח "מזהה" שהוא בעצם פקודה. זו SQL injection, מהפרצות הוותיקות והנפוצות שיש. הפתרון: parameters. ה-SQL נשלח עם ?, והערכים נשלחים בנפרד, כך שהם תמיד נתונים ואף פעם לא קוד. """The database: two tables, and the engine that connects to them.

DATABASE_URL says which database. The default is a SQLite file, agent.db.
"""

from datetime import UTC, datetime
from typing import Any

from sqlalchemy import Engine, ForeignKey, String, Text, create_engine, event
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column
from sqlalchemy.pool import StaticPool


def now() -> datetime:
    return datetime.now(UTC)


class Base(DeclarativeBase):
    """Every table class inherits from this, so SQLAlchemy knows about all of them."""


class ConversationRow(Base):
    """One row of the conversations table."""

    __tablename__ = "conversations"

    id: Mapped[str] = mapped_column(String(32), primary_key=True)
    created_at: Mapped[datetime] = mapped_column(default=now)


class MessageRow(Base):
    """One row of the messages table: one message, in one conversation."""

    __tablename__ = "messages"

    id: Mapped[int] = mapped_column(primary_key=True)
    conversation_id: Mapped[str] = mapped_column(ForeignKey("conversations.id"), index=True)
    role: Mapped[str] = mapped_column(String(16))
    content: Mapped[str] = mapped_column(Text)
    created_at: Mapped[datetime] = mapped_column(default=now)


def turn_on_foreign_keys(connection: Any, record: Any) -> None:
    """SQLite ignores foreign keys unless every new connection asks for them."""
    connection.execute("PRAGMA foreign_keys = ON")


def make_engine(url: str) -> Engine:
    """Connect to the database at `url`, and create the tables that do not exist yet."""
    if url in ("sqlite://", "sqlite:///:memory:"):
        # An in-memory database lives inside one connection, so everyone shares that one.
        engine = create_engine(url, poolclass=StaticPool, connect_args={"check_same_thread": False})
    else:
        engine = create_engine(url)
    if engine.dialect.name == "sqlite":
        event.listen(engine, "connect", turn_on_foreign_keys)
    # create_all adds missing tables. It never changes a table that already exists.
    Base.metadata.create_all(engine)
    return engine

השוו ל-CREATE TABLE שכתבתם: Mapped[str] הוא עמודה NOT NULL, Mapped[str | None] הייתה מתירה ריק, index=True הוא ה-CREATE INDEX, ו-default=now ממלא את created_at בזמן UTC. השם ConversationRow ולא Conversation, כדי לא להתבלבל עם ה-schema Message של api.py: זה שורה בטבלה, וזה מה שנוסע ב-HTTP. turn_on_foreign_keys היא ה-PRAGMA מסעיף 6.4, שרצה בכל חיבור חדש.

שתי החלטות פשוטות במכוון. create_all יוצר טבלאות שחסרות, וזו הדרך הפשוטה והכנה ליצור אותן היום. ובסיס נתונים בזיכרון (sqlite://) קיים רק בתוך החיבור שיצר אותו, ולכן StaticPool גורם לכולם, גם ל-threads של FastAPI, להשתמש באותו חיבור. זה בשביל הבדיקות. שמרו: git add pyproject.toml uv.lock agent\db.py, git commit -m "Add SQLAlchemy and the database tables".

"""The core of the agent: conversations and their messages.

The terminal chat and the HTTP API both use this module, so they behave the same.
Every message is saved in the database, so conversations survive a restart.
"""

import logging
import uuid

from anthropic.types import MessageParam
from sqlalchemy import Engine, delete, select
from sqlalchemy.orm import Session, sessionmaker

from agent.db import ConversationRow, MessageRow
from agent.history import trim_history
from agent.llm import ChatClient

log = logging.getLogger(__name__)


class ConversationNotFound(Exception):
    """No conversation has this id (it was deleted, or never existed)."""


def to_param(row: MessageRow) -> MessageParam:
    """A row from the database, in the shape the model client expects."""
    if row.role == "user":
        return {"role": "user", "content": row.content}
    return {"role": "assistant", "content": row.content}


class Conversations:
    """Every conversation, by id, and the one way to add a message to it."""

    def __init__(self, client: ChatClient, max_turns: int, engine: Engine) -> None:
        self.client = client
        self.max_turns = max_turns
        self.sessions = sessionmaker(engine)

    def _require(self, session: Session, conversation_id: str) -> None:
        if session.get(ConversationRow, conversation_id) is None:
            raise ConversationNotFound(conversation_id)

    def start(self) -> str:
        """Open a new, empty conversation and return its id."""
        conversation_id = uuid.uuid4().hex
        with self.sessions.begin() as session:
            session.add(ConversationRow(id=conversation_id))
        return conversation_id

    def messages(self, conversation_id: str) -> list[MessageParam]:
        """Every message in this conversation, oldest first."""
        with self.sessions() as session:
            self._require(session, conversation_id)
            rows = session.scalars(
                select(MessageRow)
                .where(MessageRow.conversation_id == conversation_id)
                .order_by(MessageRow.id)
            )
            return [to_param(row) for row in rows]

    def send(self, conversation_id: str, text: str) -> str:
        """Send the user's message with the recent history, and save both messages."""
        history = self.messages(conversation_id)
        # The model sees only the last turns; the database keeps all of them.
        prompt = trim_history(history, self.max_turns) + [{"role": "user", "content": text}]
        log.info("sending %d messages", len(prompt))
        reply = self.client.reply(prompt)  # if this fails, nothing was saved
        # One transaction: both messages are saved, or neither is.
        with self.sessions.begin() as session:
            session.add(MessageRow(conversation_id=conversation_id, role="user", content=text))
            session.add(
                MessageRow(conversation_id=conversation_id, role="assistant", content=reply)
            )
        return reply

    def reset(self, conversation_id: str) -> None:
        """Delete every message in this conversation, but keep the conversation."""
        with self.sessions.begin() as session:
            self._require(session, conversation_id)
            session.execute(delete(MessageRow).where(MessageRow.conversation_id == conversation_id))

    def delete(self, conversation_id: str) -> None:
        """Delete the conversation and its messages. Its id stops working."""
        with self.sessions.begin() as session:
            self._require(session, conversation_id)
            session.execute(delete(MessageRow).where(MessageRow.conversation_id == conversation_id))
            session.execute(delete(ConversationRow).where(ConversationRow.id == conversation_id))

אותן חמש מתודות, אותן חתימות, אותה חריגה. השינוי היחיד בממשק הוא engine בבנאי. sessions.begin() פותח session ו-transaction: ביציאה מה-with בלי חריגה הוא עושה COMMIT, ועם חריגה ROLLBACK. send בנוי לפי ה-callout מסעיף 6.6: קריאה, שאלה למודל מחוץ ל-transaction, ואז כתיבה אחת של שתי השורות. ה-messages.pop() מפרק 5 נעלם, כי כבר אין מה לבטל. ו-delete מוחק הודעות ושיחה באותה transaction: את השיחה אי אפשר למחוק קודם, כי ה-foreign key של ההודעות מצביע עליה.

from agent.conversations import Conversations
from agent.db import make_engine
from agent.llm import MockClient


def test_a_conversation_survives_a_restart(tmp_path):
    url = f"sqlite:///{tmp_path / 'test.db'}"  # pytest gives every test its own empty folder
    first_run = make_engine(url)
    before = Conversations(MockClient(), 10, first_run)
    conversation_id = before.start()
    before.send(conversation_id, "remember me")
    first_run.dispose()  # close every connection, as a stopped server does

    second_run = make_engine(url)  # a new engine on the same file: a restarted server
    after = Conversations(MockClient(), 10, second_run)
    messages = after.messages(conversation_id)
    second_run.dispose()

    assert messages[0]["content"] == "remember me"


def test_everything_is_saved_but_the_model_sees_only_recent_turns():
    conversations = Conversations(MockClient(), 2, make_engine("sqlite://"))

def alembic_config(url: str) -> Config:
    """What the alembic command reads from alembic.ini, for the database at `url`."""
    config = Config()
    config.set_main_option("script_location", str(MIGRATIONS))
    config.attributes["url"] = url  # migrations/env.py reads it from here

def upgrade(url: str, revision: str = "head") -> None:
    """Run the migrations on the database at `url`, like `alembic upgrade head`."""
    command.upgrade(alembic_config(url), revision)


def check_schema(engine: Engine) -> None:
    """Refuse to work with a database that is behind the code."""
    scripts = ScriptDirectory(str(MIGRATIONS))
    head = scripts.get_current_head()
    with engine.connect() as connection:
        current = MigrationContext.configure(connection).get_current_revision()
    if current == head:
        return
    if current is None:
        raise DatabaseNotReady(
            "The database has no migration history. A new database: run "
            "`uv run alembic upgrade head`. One from before migrations: see `alembic stamp`."
        )
    try:
        scripts.get_revision(current)
    except CommandError:
        # A revision we do not know: newer code has already migrated this database.
        # That is fine (the old code must keep working during a deploy), but say so.
        log.warning("database is at %s, newer than this code (%s)", current, head)
        return
    raise DatabaseNotReady(
        f"The database is at revision {current}, the code needs {head}. "
        "Run `uv run alembic upgrade head`."
    )

7.7SQLite, batch mode, ומה ישתנה ב-Postgres

למה Alembic כתב with op.batch_alter_table(...) ולא פקודה פשוטה? כי SQLite יודע מעט מאוד ALTER TABLE. על המחשב הזה (SQLite 3.50): ADD COLUMN ו-DROP COLUMN עובדים, אבל שינוי של עמודה קיימת לא קיים בשפה:

op.alter_column(..., nullable=False) without batch mode, on SQLite
sqlite3.OperationalError: near "ALTER": syntax error
[SQL: ALTER TABLE t ALTER COLUMN title SET NOT NULL]

Batch mode עוקף את זה: הוא יוצר טבלה חדשה בשם _alembic_tmp_conversations במבנה החדש, מעתיק אליה את כל השורות, מוחק את הישנה ומשנה לחדשה את השם. זה גם ההסבר לשני דברים שראיתם. ההעתקה נכשלה על שורה עם NULL כי הטבלה החדשה כבר הייתה NOT NULL. וטבלת העזר נשארה, כי Alembic מודיע Will assume non-transactional DDL: עם הדרייבר של Python ל-SQLite, פקודות מבנה לא מתבטלות כשמשהו נכשל באמצע. מכאן שלושה כללים: גיבוי לפני כל migration, ניסיון על עותק כשיש ספק, ו-foreign keys כבויים בזמן ה-migration, אחרת מחיקת הטבלה הישנה הייתה נחסמת בגלל messages. זו הסיבה ש-env.py לא משתמש ב-make_engine.

ב-Postgres, שאליו הפרויקט עובר בפרק 8, הכול פשוט יותר: batch_alter_table כותב שם ALTER TABLE conversations ALTER COLUMN title SET NOT NULL ישירות, בלי העתקה, וכל migration רץ בתוך transaction אמיתית: כישלון באמצע מבטל הכול. אותם קבצים עובדים בשני המקומות, כל עוד לא כותבים בהם SQL שרק SQLite מבין. תרגיל 1 מראה את ה-SQL של Postgres בלי להתקין אותו.

7.8Migrations ב-git ובצוות

  • Migration שרץ במקום אחר לא נערך יותר. אם 0002 כבר רץ על השרת, שינוי בקובץ לא ישפיע שם: alembic_version אומר שהוא כבר רץ. טעות מתקנים ב-migration חדש. מותר לערוך רק מה שעוד לא יצא מהמחשב שלכם (ואז downgrade מקומי, עריכה, upgrade).
  • ה-migration וקוד שמשתמש בו נכנסים לאותו pull request, והבודק קורא את ה-migration ראשון: האם הוא נועל טבלה גדולה? מוחק? תואם לקוד הישן?
  • שני ענפים, שני migrations. git ימזג אותם בלי קונפליקט, כי אלה שני קבצים שונים. אבל לשניהם אותו down_revision, והשרשרת התפצלה לשני ראשים (heads). git לא רואה את זה; Alembic ו-test_migrations.py כן. תרגיל 4.
  • הסדר בעדכון גרסה: גיבוי, alembic upgrade head, ואז הקוד החדש. בגלל expand, migrate, contract, הקוד הישן ממשיך לעבוד בין שני הצעדים.
  • Rollback של קוד הוא כמעט תמיד בטוח, כי המבנה החדש תואם לקוד הישן. downgrade בשרת הוא צעד אחרון: הוא עלול למחוק נתונים, ולכן צוותים רבים מעדיפים לתקן קדימה, עם migration חדש. גיבוי הוא הדרך החזרה האמיתית.

scripts\probe.py
"""Find out at which step a request to a URL fails: DNS, connection, or HTTP.

Run it with: uv run python scripts/probe.py http://127.0.0.1:8000/
"""

import socket
import sys
from http.client import HTTPConnection, HTTPSConnection
from urllib.parse import urlsplit


def probe(url: str) -> bool:
    """Walk the steps one by one and stop at the first that fails."""
    parts = urlsplit(url)
    host = parts.hostname or ""
    port = parts.port or (443 if parts.scheme == "https" else 80)
    path = parts.path or "/"

    print(f"1. DNS      {host}")
    try:
        found = socket.getaddrinfo(host, port, type=socket.SOCK_STREAM)
    except socket.gaierror as error:
        print(f"   FAILED   the name does not resolve: {error}")
        return False
    print(f"   ok       {', '.join(str(info[4][0]) for info in found)}")

    print(f"2. CONNECT port {port}")
    try:
        socket.create_connection((host, port), timeout=5).close()
    except OSError as error:
        print(f"   FAILED   nobody answers on this port: {error}")
        return False
    print("   ok")

    step = "TLS + HTTP" if parts.scheme == "https" else "HTTP"
    print(f"3. {step}  GET {path}")
    connection_type = HTTPSConnection if parts.scheme == "https" else HTTPConnection
    connection = connection_type(host, port, timeout=10)
    try:
        connection.request("GET", path)
        response = connection.getresponse()
    except OSError as error:
        print(f"   FAILED   {error}")
        return False
    finally:
        connection.close()
    print(f"   answer   {response.status} {response.reason}")
    return response.status < 400


if __name__ == "__main__":
    sys.exit(0 if probe(sys.argv[1]) else 1)

scripts\ask.py
"""Ask the agent's HTTP API one question, from another program.

Run it with: uv run python scripts/ask.py "your message" [--conversation ID]

It reads AGENT_API_KEY (and AGENT_URL, default http://127.0.0.1:8000) from the
environment or from .env, like the server does.
"""

import argparse
import json
import os
import sys
import urllib.error
import urllib.request

from dotenv import load_dotenv


def ask(url: str, key: str, message: str, conversation_id: str | None) -> dict[str, object]:
    """POST /chat and return the JSON reply. Raises urllib errors on failure."""
    body = json.dumps({"message": message, "conversation_id": conversation_id})
    request = urllib.request.Request(
        f"{url}/chat",
        data=body.encode("utf-8"),
        headers={"Content-Type": "application/json", "X-API-Key": key},
        method="POST",
    )
    # Always a timeout: without one, a server that never answers blocks us forever.
    with urllib.request.urlopen(request, timeout=30) as response:
        reply: dict[str, object] = json.load(response)
        return reply


def main() -> None:
    load_dotenv()
    parser = argparse.ArgumentParser(description="Send one message to the agent's API.")
    parser.add_argument("message")
    parser.add_argument("--conversation", help="continue this conversation id")
    args = parser.parse_args()

    url = os.getenv("AGENT_URL", "http://127.0.0.1:8000")
    key = os.getenv("AGENT_API_KEY")
    if not key:
        sys.exit("AGENT_API_KEY is not set.")

    try:
        data = ask(url, key, args.message, args.conversation)
    except urllib.error.HTTPError as error:
        # The server answered, with an error status (4xx or 5xx). Its body says why.
        detail = json.load(error).get("detail")
        sys.exit(f"The API answered {error.code}: {detail}")
    except urllib.error.URLError as error:
        # No answer at all: DNS or connection failed (chapter 4).
        sys.exit(f"Could not reach {url}: {error.reason}")

    print(data["reply"])
    print(f"(conversation {data['conversation_id']}, turns: {data['turns']})")


if __name__ == "__main__":
    main()

"""How much does an index help? Times one query before and after CREATE INDEX.

Run it with: uv run python scripts/index_lab.py
Everything happens in an in-memory SQLite database, so no file is left behind.
"""

import sqlite3
import time

CONVERSATIONS = 10_000
MESSAGES_PER_CONVERSATION = 50
QUERY = "SELECT content FROM messages WHERE conversation_id = ? ORDER BY id"


def fill(db: sqlite3.Connection) -> None:
    """Create the messages table and fill it with fake messages."""
    db.execute(
        "CREATE TABLE messages (id INTEGER PRIMARY KEY, conversation_id TEXT NOT NULL,"
        " role TEXT NOT NULL, content TEXT NOT NULL)"
    )
    rows = (
        (f"c{c}", "user" if m % 2 == 0 else "assistant", f"message {m} of conversation {c}")
        for c in range(CONVERSATIONS)
        for m in range(MESSAGES_PER_CONVERSATION)
    )
    # The ? placeholders: the values travel separately from the SQL text.
    db.executemany("INSERT INTO messages (conversation_id, role, content) VALUES (?, ?, ?)", rows)
    db.commit()


def time_queries(db: sqlite3.Connection, label: str, repeats: int = 200) -> None:
    """Run the query for `repeats` different conversations and print the average time."""
    plan = db.execute("EXPLAIN QUERY PLAN " + QUERY, ("c1",)).fetchall()
    start = time.perf_counter()
    for i in range(repeats):
        db.execute(QUERY, (f"c{i * 37 % CONVERSATIONS}",)).fetchall()
    average_ms = (time.perf_counter() - start) / repeats * 1000
    print(f"{label}: {average_ms:.3f} ms per query  plan: {plan[0][3]}")


def main() -> None:
    db = sqlite3.connect(":memory:")
    fill(db)
    count = db.execute("SELECT COUNT(*) FROM messages").fetchone()[0]
    print(f"{count:,} messages in {CONVERSATIONS:,} conversations")
    time_queries(db, "without index")
    start = time.perf_counter()
    db.execute("CREATE INDEX ix_messages_conversation_id ON messages (conversation_id)")
    print(f"CREATE INDEX took {(time.perf_counter() - start) * 1000:.0f} ms")
    time_queries(db, "with index   ")
    db.close()


if __name__ == "__main__":
    main()

6תוכנית ל-user_id

אין תשובה יחידה. דוגמה לתוכנית סבירה:

  1. Expand (נעשה, 0005): עמודה ריקה. קוד ישן וחדש עובדים.
  2. קוד: השרת מזהה משתמש לפי המפתח: טבלה קטנה של מפתחות ובעליהם (עוד migration של expand), או בינתיים שם קבוע מ-.env. ה-terminal כותב "local". כל שיחה חדשה נשמרת עם user_id. הקוד עדיין לא דורש אותו בקריאה, כי יש שורות ישנות בלי. יוצא לשרת לבד; מחכים שאין תהליך ישן.
  3. Migrate: migration שממלא את השורות הריקות. אם יש רק משתמש אחד אמיתי, את השם שלו; אחרת ערך מפורש כמו "unknown", ולא ניחוש.
  4. קוד: גרסה שמסננת לפי user_id (כל אחד רואה רק את השיחות שלו, וזו כבר שאלה של אבטחה, פרק 14), ושמניחה שהערך קיים.
  5. Contract: NOT NULL, ואינדקס על user_id אם מסננים לפיו.

חזרה אחורה: אחרי שלבים 1 עד 3, החזרת הקוד הקודם בטוחה, כי הוא מתעלם מהעמודה. אחרי 5, קוד ישן ייפול כמו בסוף 7.6, ולכן 5 רץ רק כשאין שום כוונה לחזור לגרסה שלפני 2. downgrade של 3 לא יודע אילו שורות היו ריקות, ולכן downgrade() שלו יכול להיות pass עם הערה שמסבירה למה.
