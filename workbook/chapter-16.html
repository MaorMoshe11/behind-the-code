מה זה AI agent

מה ההבדל בין קריאה אחת למודל, workflow ו-agent, איך כותבים ביד את הלולאה שבה המודל מבקש כלי והתוכנית מפעילה אותו, ומתי עדיף לא לבנות סוכן בכלל.

בסוף הפרק תדעו

  • להבחין בין קריאה אחת, workflow ו-agent, ולהסביר מי מחליט על הצעד הבא בכל אחד.
  • להגדיר כלי (שם, תיאור, JSON schema) ולקרוא את ההודעות של tool use: tool_use, tool_result, stop_reason.
  • לכתוב ביד לולאת סוכן עם כלי אחד, מגבלת צעדים, שגיאת כלי שחוזרת למודל, ושורת לוג ומדד לכל צעד.
  • לבדוק לולאה כזו בלי מודל אמיתי, עם mock שמבקש כלים לפי תסריט.
  • לזהות מה משתבש בלולאות, ולבחור את הצורה הפשוטה ביותר שעובדת.

זמן משוער: ארבע עד חמש שעות. מה צריך: הפרויקט מסוף פרק 15, ושירות ההערות מפרק 11 רץ בחלון נפרד (בלי Docker). הכול במצב mock, בלי מפתח ובלי עלות.

16.1הבעיה: צ'אט שרק מדבר

שירות ההערות מפרק 11 עובד, והצ'אט מדבר איתו. שמרו הערה, ושאלו עליה, בגרסה 0.15.0:

ה-mock רק מחזיר את מה שכתבתם, אבל הוא לא מסתיר דבר: גם מודל אמיתי היה מקבל בדיוק את מה שהוא קיבל, את הטקסט של השאלה. שורת הלוג model replied ב-agent.log מראה "messages": 1. ההערה יושבת בבסיס הנתונים של שירות ההערות, ואין שום דרך שבה היא תגיע אל המודל. אז מה עונה מודל אמיתי? משהו כזה:

I don't have access to your notes. If you paste them here, I can help you find
what you saved about milk.

ובמקרה הגרוע, תשובה בטוחה בעצמה שהומצאה מכלום ("You saved: buy milk and eggs"). על התאריך הוא יענה לפי מה שהוא זוכר מהאימון, או יודה שאינו יודע. בשני המקרים הבעיה זהה: המודל רק מייצר טקסט. הוא לא יכול לקרוא קובץ, לשאול שירות או לבדוק את השעון. כל "פעולה" במערכת שלכם היא פקודה שאדם הקליד (/notes) או קוד שכתבתם מראש. הפרק הזה נותן למודל דרך לבקש פעולה, ולתוכנית שלכם דרך לבצע אותה ולהחזיר לו את התוצאה.

1. single call

ההבדל בין הצורות הוא מי מחליט מה הצעד הבא. בקריאה אחת אין צעד הבא. ב-workflow הקוד שלכם קובע את הסדר מראש. ב-agent המודל מחליט, בכל סיבוב, אם לבקש כלי או לענות.

16.3קריאה אחת, workflow, agent

קריאה אחת (single LLM call) היא מה שהפרויקט עושה מפרק 1: שולחים את השיחה, מקבלים תשובה. רוב המשימות של מודלי שפה הן כאלה: לסכם, לתרגם, לסווג, לחלץ שדות, לענות על שאלה מתוך טקסט שנתתם. קל לבדוק אותה, מחירה ידוע מראש, והיא מהירה.

Workflow הוא כמה צעדים שהסדר שלהם כתוב בקוד. חלק מהצעדים הם קריאות למודל, חלק קוד רגיל. שלוש תבניות נפוצות, כל אחת עם דוגמה מהפרויקט:

תבניתמה היאדוגמה בפרויקט
Prompt chainingהפלט של קריאה אחת הוא הקלט של הבאה, ובדיקה בקוד ביניהןלסכם שיחה ארוכה, ואז לכתוב לה כותרת מתוך הסיכום
Routingקריאה קטנה מסווגת את הבקשה, והקוד שולח אותה למסלול המתאים"שאלה על קוד" לפרומפט אחד, "שאלה כללית" לאחר, אולי למודל זול יותר
קריאות במקביל (parallelization)כמה קריאות עצמאיות בבת אחת, והקוד מאחדלבדוק תשובה בשלוש קריאות שונות (עובדות, טון, אורך) ולאחד את ההערות

גם /notes מפרק 11 הוא מעין workflow קטן: הקוד מזהה פקודה ומחליט להפעיל את השירות. המודל לא מחליט שום דבר.

Agent (סוכן) הוא לולאה שבה המודל מחליט מה הצעד הבא. בכל סיבוב הוא מקבל את כל מה שקרה עד עכשיו, ובוחר: לבקש כלי, או לענות ולסיים. הקוד שלכם מפעיל את הכלים ושומר על גבולות: אילו כלים קיימים, כמה סיבובים מותר, מה קורה כשמשהו נכשל. זה כל ההבדל. המילה "agent" משמשת היום לכל דבר, משיווק של צ'אטבוט ועד מערכות גדולות. בחוברת היא אומרת דבר אחד מדויק: מודל שבוחר בעצמו את הצעד הבא, בלולאה, עם כלים, עד שהוא מחליט שסיים. אין בזה קסם ואין "חשיבה עצמאית": יש לולאת for שאתם כותבים.

חמישה כללים, וכל אחד מהם הוא שגיאה של 400 או באג שקט אם שוכחים אותו:

  • השיחה נושאת את שניהם. הודעה 2 (הבקשה) והודעה 3 (התוצאה) נשלחות בקריאה הבאה. ה-API לא זוכר דבר בין קריאות (פרק 1), ותוצאה בלי הבקשה שלה נדחית.
  • מחזירים את כל התשובה של המודל, כמו שהיא. לא רק את הטקסט. אצל מודלים שחושבים לפני שהם עונים (thinking, פועל כברירת מחדל ב-claude-opus-5-5) יש בתשובה גם בלוקים של thinking, וצריך להחזיר גם אותם, בלי שינוי.
  • כל תוצאה קשורה לבקשה שלה ב-tool_use_id. המודל יכול לבקש כמה כלים בתשובה אחת. כל התוצאות של אותו סיבוב נשלחות בהודעת user אחת.
  • כישלון הוא תוצאה. כלי שנכשל מחזיר tool_result עם "is_error": true והסבר קצר. המודל קורא אותו, ויכול לנסות אחרת או לספר למשתמש.
  • הקלט הוא קלט מבחוץ. המודל כתב אותו, אז הוא יכול להיות שגוי, חסר או מוזר, בדיוק כמו גוף של בקשת HTTP (פרק 14). בודקים אותו לפני שמפעילים משהו.

ערכי stop_reason שהלולאה צריכה להכיר: end_turn (המודל סיים), tool_use (הוא מחכה לתוצאות), max_tokens (נגמר לו המקום באמצע), refusal (הוא סירב, והטקסט לא שמיש). יש גם pause_turn, ששייך לכלים שרצים בצד של Anthropic ולא לכלים שלכם; בפרויקט הזה הוא לא יופיע.

16.5הלולאה, ביד

ל-SDK יש עוזר שמריץ את הלולאה בשבילכם (tool runner), ויש frameworks שלמים לזה. כאן כותבים אותה בעצמכם, כדי שכל צעד יהיה מול העיניים: קריאה, בדיקת stop_reason, הפעלת הכלי, הוספת התוצאה, קריאה נוספת. ארבעים שורות:

agent\loop.py (the heart of it)
def run_tool(tools: dict[str, Tool], call: ToolUseBlock) -> ToolResultBlockParam:
    """Run one tool call. Whatever happens, the model gets a result: never an exception."""
    tool = tools.get(call.name)
    try:
        if tool is None:
            raise ToolError(f"There is no tool named {call.name!r}.")
        content, is_error = tool.run(call.input), False
    except ToolError as error:  # an expected failure: the message is written for the model
        content, is_error = str(error), True
    except Exception:  # a bug in our tool: the details go to our log, not to the model
        log.exception("tool %s crashed", call.name)
        content, is_error = "The tool failed unexpectedly.", True
    outcome = "error" if is_error else "ok"
    AGENT_TOOL_CALLS.labels(call.name if tool else "unknown", outcome).inc()
    level = logging.WARNING if is_error else logging.INFO
    log.log(level, "tool %s: %s", call.name, outcome, extra={"tool": call.name, "outcome": outcome})
    return {"type": "tool_result", "tool_use_id": call.id, "content": content, "is_error": is_error}


def run_agent(
    client: AgentClient, messages: list[MessageParam], tools: Sequence[Tool], max_steps: int
) -> AgentRun:
    """Run the loop on a copy of `messages` (the conversation so far, ending with the question)."""
    messages = list(messages)  # our own list: the caller's is not changed
    by_name = {tool.name: tool for tool in tools}
    params = [tool.param() for tool in tools]
    tool_calls = 0
    for step in range(1, max_steps + 1):
        response = client.create(messages, params)
        log.info("agent step %d: %s", step, response.stop_reason, extra={...})  # shortened
        # Its whole answer goes back next time, unchanged: text, tool requests, thinking.
        messages.append({"role": "assistant", "content": response.content})
        if response.stop_reason != "tool_use":  # it answered (or refused, or ran out of room)
            stop = response.stop_reason or "unknown"
            return finish(AgentRun(text_of(response), stop, step, tool_calls, messages))
        calls = [block for block in response.content if block.type == "tool_use"]
        # Every result of this step in ONE user message, each one tied to its request by id.
        messages.append({"role": "user", "content": [run_tool(by_name, call) for call in calls]})
        tool_calls += len(calls)
    log.warning("agent stopped after %d steps", max_steps, extra={"tool_calls": tool_calls})
    reply = GAVE_UP.format(steps=max_steps)
    return finish(AgentRun(reply, "max_steps", max_steps, tool_calls, messages))

שלוש החלטות שכדאי לשים לב אליהן. for, לא while True: הגבול על מספר הצעדים הוא חלק מהלולאה, לא תוספת. מודל שמבקש את אותו כלי שוב ושוב יעצור אחרי max_steps, עם תשובה שאומרת זאת, במקום לשרוף כסף עד שמישהו ישים לב. run_tool לא זורק לעולם: כלי לא מוכר, קלט שגוי, שירות שנפל, ואפילו באג בכלי, כולם הופכים ל-tool_result עם is_error. הלולאה ממשיכה, והמודל מחליט מה לומר. פרטי הבאג נכתבים ללוג שלכם, לא למודל. התווית של המדד היא "unknown" לכלי לא מוכר, ולא השם שהמודל המציא: מדדים מקבלים מעט ערכים ידועים בלבד (פרק 13).

ה-AgentRun שהלולאה מחזירה מחזיק את התשובה, סיבת העצירה, מספר הצעדים והכלים, וכל ההודעות של הריצה. מי שקורא ל-run_agent בוחר מה לעשות בהן.

agent\tools.py (the definition)
class ToolError(Exception):
    """The tool could not do what was asked. The message goes back to the model."""


@dataclass(frozen=True)
class Tool:
    name: str
    description: str  # the model reads this to decide when to call the tool
    input_schema: dict[str, Any]  # JSON schema of the input the model must send
    run: Callable[[dict[str, Any]], str]  # our code: takes the input, returns text for the model

    def param(self) -> ToolParam:
        """The tool as the API expects it in `tools`: everything except our code."""
        return {
            "name": self.name,
            "description": self.description,
            "input_schema": self.input_schema,
        }

notes_tool(notes, conversation_id) בונה את הכלי עם התיאור וה-schema מ-16.4. הלב שלו, הפונקציה run:

agent\tools.py (inside notes_tool(notes, conversation_id))
    def run(tool_input: dict[str, Any]) -> str:
        # The model wrote this input. Check it like any other input from outside.
        unknown = set(tool_input) - {"search"}
        if unknown:
            raise ToolError(f"Unknown input field(s): {', '.join(sorted(unknown))}.")

CALL = re.compile(r"\[mock:call (\w+) (\{.*?\})\]")  # [mock:call list_notes {"search": 42}]
LOOP = "[mock:loop]"  # ask for the tool again after every result: a loop that never ends
NOTES = re.compile(r"\bnotes\b", re.IGNORECASE)  # "what is in my notes?" -> list_notes
ABOUT = re.compile(r"\babout ([^?.!\n]+)", re.IGNORECASE)  # "... about milk?" -> search "milk"


def wanted_call(question: str, offered: set[str]) -> tuple[str, dict[str, Any]] | None:
    """The tool call the mock 'decides' to make for this question, or None for a plain answer."""
    scripted = CALL.search(question)
    if scripted:  # exactly what the message says, offered or not: for testing bad calls
        return scripted.group(1), json.loads(scripted.group(2))
    if "list_notes" in offered and NOTES.search(question):
        about = ABOUT.search(question)
        return "list_notes", {"search": about.group(1).strip()} if about else {}
    return None

create() קורא לה על השאלה האחרונה של המשתמש. אם ההודעה האחרונה היא עדיין השאלה, ויש קריאה, הוא מחזיר tool_use עם stop_reason של "tool_use"; אחרת, טקסט עם "end_turn". אחרי תוצאה, ה-mock עונה בטקסט שמצטט אותה ("I looked it up. The tool said:", או "I tried, but the tool failed:"). הוא גם מדווח input_tokens שגדל עם כל צעד, כי כל השיחה נשלחת שוב. המספר מומצא (תו לכל ארבעה), אבל הצורה שלו נכונה.

    def answer(self, conversation_id: str, prompt: list[MessageParam]) -> str:
        """No tools: one model call, as before. With tools: the agent loop."""
        if self.notes is None:
            return self.client.reply(prompt)
        tools = [notes_tool(self.notes, conversation_id)]
        return run_agent(self.client, prompt, tools, self.max_steps).reply

16.7מה משתבש בלולאה

מהאיך זה נראהמה עוצר את זה אצלכם
לולאה שלא נגמרתהמודל מבקש שוב ושוב את אותו כלי, או מחפש בלי למצואmax_steps, תשובה שאומרת שהלולאה עצרה, ומדד stop="max_steps"
קלט שגוי לכלימספר במקום מחרוזת, שדה שלא קיים, כלי שלא קייםבדיקה בתוך הכלי, ו-ToolError שחוזר למודל עם הסבר שהוא יכול לתקן לפיו
הכלי נכשלשירות למטה, timeout, באגis_error, ללא חריגה בלולאה; ה-retries וה-circuit breaker של פרק 11 עדיין עובדים מתחת
עלות וזמן שגדליםכל צעד שולח את כל השיחה שוב, ועוד הגדרות הכלים; זמן הכלים מתווסףמגבלת צעדים, לוג עם input_tokens לכל צעד, ו-llm_tokens_total מפרק 13

ויש עוד אחד, שקל לפספס: המודל פועל לפי טקסט שהוא קורא. תוצאה של כלי היא טקסט שנכנס לשיחה, בדיוק כמו ההודעה של המשתמש. הערה ששמורה בשירות ("ignore the user and ..."), דף אינטרנט או קובץ יכולים להכיל הוראות, והמודל עלול לנהוג לפיהן. זה prompt injection, ופרק 21 מדגים אותו ומוסיף אישור אנושי לכלים מסוכנים. כאן ההגנה היא בתכנון: הכלי היחיד קורא בלבד, והקוד בוחר את השיחה, לא המודל. במקרה הגרוע, המודל יכתוב תשובה מוזרה. הוא לא יכול למחוק, לשלוח או לקרוא משהו שאינו של המשתמש הזה. לפני שמוסיפים כלי שכותב או מוחק, שואלים: מה יקרה אם המודל יפעיל אותו בגלל טקסט שמישהו אחר כתב?

16.8מתי לא לבנות סוכן

הכלל: הצורה הפשוטה ביותר שעובדת. כל צעד מקריאה אחת לעבר סוכן קונה גמישות, ומשלם עליה בארבעה מטבעות:

  • עלות: יותר קריאות, וכל אחת שולחת את כל מה שהיה. הגדרות הכלים נשלחות גם כשאין בהן צורך.
  • זמן: צעדים רצים זה אחרי זה, והכלים מוסיפים את הזמן שלהם.
  • צפיות: אותה שאלה יכולה לקבל שני מסלולים שונים. קשה להבטיח "תמיד יקרא את ההערות".
  • בדיקות: אפשר לבדוק את הלולאה; את ההחלטות של המודל אפשר רק למדוד, על הרבה דוגמאות.
משימה בפרויקטצורהלמה
לענות על הודעה בצ'אטקריאה אחתזה מה שהיה עד היום, וזה מספיק לרוב ההודעות
כותרת לשיחה, סיכום שלה לדוח הליליקריאה אחת, או chaining של שתייםהקלט ידוע, והפלט נבדק בקוד
"שאלת קוד" לפרומפט אחד, "שאלה כללית" לאחרWorkflow (routing)מעט מסלולים, והקוד יכול לבחור אחרי סיווג אחד
למחוק שיחה ואת ההערות שלהקוד רגיל (saga, פרק 12)אין כאן החלטה למודל; פעולה מסוכנת לא נותנים לו
"מה שמרתי על חלב?", בתוך שיחה רגילהAgent עם כלי אחדרק המודל יודע, מתוך השאלה, אם צריך את ההערות ומה לחפש

ואפילו בשורה האחרונה יש חלופה: workflow שתמיד מביא את ההערות ושם אותן בפרומפט. הוא צפוי יותר וזול יותר בשאלה על הערות, ויקר יותר בכל שאר ההודעות. איזו מהן נכונה תלוי במספרים: כמה הודעות הן על הערות, כמה הערות יש, וכמה זמן לוקח לשירות לענות. בתרגיל 6 תמדדו ותחליטו, ותכתבו את ההחלטה ב-ADR (פרק 15). ארבע שאלות לפני כל סוכן: האם המשימה באמת לא ידועה מראש? האם התוצאה שווה את העלות והזמן? האם המודל מסוגל לה? ואם הוא יטעה, האם תדעו ותוכלו לתקן?

16.12מילון מונחים

single LLM call
קריאה אחת למודל: הודעות נכנסות, תשובה יוצאת.
workflow
כמה צעדים, חלקם קריאות למודל, בסדר שהקוד קובע מראש.
prompt chaining
הפלט של קריאה אחת הוא הקלט של הבאה.
routing
קריאה שמסווגת בקשה, והקוד שולח אותה למסלול המתאים.
agent
מודל שבוחר את הצעד הבא בלולאה, עם כלים, עד שהוא מחליט שסיים.
tool
שם, תיאור ו-JSON schema של פעולה שהמודל יכול לבקש; הקוד שלכם מבצע אותה.
tool_use
בלוק בתשובת המודל: בקשה להפעיל כלי, עם מזהה, שם וקלט.
tool_result
בלוק בהודעת user: התוצאה של בקשה, עם ה-tool_use_id שלה.
stop_reason
למה המודל הפסיק: end_turn, tool_use, max_tokens, refusal.
agent loop
קריאה, בדיקת stop_reason, הפעלת כלים, החזרת תוצאות, וחוזר חלילה.
max steps
הגבול על מספר הקריאות למודל בריצה אחת.
is_error
סימון של tool_result שהכלי נכשל; המודל קורא אותו ומחליט מה לומר.
prompt injection
הוראות בתוך טקסט שהמודל קורא, שגורמות לו לפעול נגד מי שהפעיל אותו.

16.13מה הלאה

כתבתם סוכן ביד, ועכשיו אתם יודעים מה יש בתוך כל כלי שנקרא "agent": מודל, כלים, ולולאה שמחברת ביניהם. אותה לולאה בדיוק, עם כלים לקריאת קבצים, עריכה והרצת פקודות, היא coding agent: התוכנה שכותבת היום חלק גדול מהקוד בצוותים. השאלה שנשארת היא לא איך לבנות אחד כזה, אלא איך לעבוד עם אחד: מה למסור לו, איך לתדרך אותו, ואיך לבדוק את מה שהחזיר לפני שזה נכנס ל-main. זה פרק 17: לעבוד עם סוכנים ביום-יום.
