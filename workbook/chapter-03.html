3.1הבעיה: "בדקתי, זה עבד"

בפרק 1 מצאתם באג ב-trim_history: היא שמרה 3 הודעות במקום 6, והשיחה התחילה בתשובה של assistant. מצאתם אותו כי מישהו כתב לכם קובץ שמדפיס "ציפיתי ל-6, קיבלתי 3". בפרק 2, ב-review של /history, אותה טעות בדיוק (הודעות במקום תורות) התגלתה רק כשהרצתם את הקוד ביד.

עכשיו הסוכן צריך באמת לחתוך שיחות ארוכות, כי כל תור שולח את כל השיחה ועולה יותר. נניח שאתם מכניסים את trim_history לסוכן. איך תדעו שהיא עובדת? תפתחו את הצ'אט, תכתבו אחת-עשרה הודעות, ותספרו. ובשבוע הבא, אחרי שינוי קטן ב-/reset, שוב. ובחודש הבא, כשמישהו בצוות "ינקה" את הפונקציה ויכתוב messages[-max_turns:], אף אחד לא יספור, והבאג יגיע למשתמש.

בדיקה ידנית היא זיכרון של אדם: היא נשכחת, היא איטית, והיא בודקת רק את מה שנזכרתם לבדוק. ויש עוד שלוש בעיות שגדלות עם הקוד. הכול נמצא ב-chat.py אחד, ואי אפשר לבדוק חלק ממנו בלי להריץ את כולו. ה-reviewer מבזבז זמן על יבוא מיותר ועל רווחים, דברים שמכונה רואה בשנייה. וכשמשהו נכשל אצל משתמש, נשארת הודעה אחת במסך ושום עקבות. הפרק עונה על ארבעתן, בסדר הזה: בדיקות, חבילה, כלים אוטומטיים, ושגיאות עם logs.

3.3pytest בחמש דקות

בדיקה אוטומטית (automated test) היא פונקציה שמריצה חלק מהקוד ובודקת שהתוצאה היא מה שציפיתם. pytest הוא הכלי המקובל ב-Python להריץ אותן. הוא מחפש קבצים ששמם מתחיל ב-test_, ובתוכם פונקציות ששמן מתחיל ב-test_. בדיקה היא assert רגיל: אם התנאי שקרי, הבדיקה נכשלת ו-pytest מדפיס את הערכים שהיו בו. כל בדיקה רצה בנפרד, וכישלון של אחת לא עוצר את האחרות.

רוב הבדיקות בנויות משלושה שלבים: מכינים קלט (arrange), מריצים (act), ובודקים (assert). מה הופך בדיקה לטובה:

  • השם אומר מה נבדק, כמשפט. כשהיא תיכשל בעוד חצי שנה, השם הוא הדבר הראשון שתקראו.
  • מהירה ודטרמיניסטית: אותה תוצאה בכל הרצה, בלי רשת ובלי שעון. בדיקה שנכשלת "לפעמים" מלמדת את כולם להתעלם מכישלונות.
  • בודקת התנהגות, לא מימוש: "השיחה מתחילה בהודעה של user", ולא "הפונקציה משתמשת ב-slice".
  • ראיתם אותה נכשלת. בדיקה שמעולם לא נכשלה אולי לא בודקת כלום. לכן בדוגמה המודרכת תחזירו את הבאג של פרק 1, בכוונה.

agent\history.py
"""The conversation history, and how it is kept short."""

from anthropic.types import MessageParam


def trim_history(messages: list[MessageParam], max_turns: int) -> list[MessageParam]:
    """Keep only the last `max_turns` turns of the conversation.

    One turn is two messages: the user's message and the assistant's reply.
    """
    if len(messages) <= max_turns * 2:
        return messages
    return messages[-max_turns * 2:]

agent\llm.py
"""Clients that turn a conversation into a reply.

ClaudeClient talks to the real Claude API. MockClient returns fake replies,
costs nothing, and is the one the tests use.
"""

from typing import Protocol

import anthropic
from anthropic.types import MessageParam


class ChatClient(Protocol):
    """Anything that can answer a conversation."""

    def reply(self, messages: list[MessageParam]) -> str: ...


class ClaudeClient:
    """Sends the whole conversation to Claude and returns the reply text."""

    def __init__(
        self, model: str, system_prompt: str, sdk: anthropic.Anthropic | None = None
    ) -> None:
        self.model = model
        self.system_prompt = system_prompt
        # Tests pass a fake SDK client here, so they never touch the network.
        self.sdk = sdk or anthropic.Anthropic()

    def reply(self, messages: list[MessageParam]) -> str:
        response = self.sdk.messages.create(
            model=self.model,
            max_tokens=16000,
            system=self.system_prompt,
            messages=messages,
        )
        if response.stop_reason == "refusal":
            return "(The model declined to answer this request.)"
        return "".join(block.text for block in response.content if block.type == "text")


class MockClient:
    """Returns a predictable fake reply. Free, offline, the same every time."""

    def reply(self, messages: list[MessageParam]) -> str:
        last_message = messages[-1]["content"]
        turn = (len(messages) + 1) // 2
        return f"[mock reply, turn {turn}] You said: {last_message}"

agent\cli.py
"""The terminal chat: reads what you type and prints the agent's replies."""

import os
import sys

import anthropic
from anthropic.types import MessageParam
from dotenv import load_dotenv
from rich.console import Console

from agent.config import SYSTEM_PROMPT, Settings, load_settings
from agent.history import trim_history
from agent.llm import ChatClient, ClaudeClient, MockClient

console = Console()


def make_client(settings: Settings) -> ChatClient:
    """Pick the mock or the real client, according to the settings."""
    if settings.mock:
        print("Running in MOCK mode - answers are fake, nothing is sent to the API.")
        return MockClient()
    if not settings.api_key:
        print("ANTHROPIC_API_KEY is not set.")
        print("Put it in a .env file, or set CHAT_MOCK=1 to run without a key.")
        sys.exit(1)
    print(f"Chatting with {settings.model}.")
    return ClaudeClient(settings.model, SYSTEM_PROMPT)


def chat_loop(client: ChatClient, settings: Settings) -> None:
    """Run the conversation until the user quits."""
    print("Type a message and press Enter. Type '/reset' to start over, 'exit' to quit.\n")
    messages: list[MessageParam] = []

    while True:
        user_text = input("you> ").strip()
        if user_text.lower() in ("exit", "quit", "bye"):
            break
        if not user_text:
            continue
        if user_text == "/reset":
            # Forget the whole conversation and start a new one.
            messages.clear()
            print("Conversation cleared. Starting over.\n")
            continue

        messages.append({"role": "user", "content": user_text})

        try:
            reply = client.reply(messages)
        # ... the three "except anthropic...." blocks, copied unchanged from chat.py ...

        messages.append({"role": "assistant", "content": reply})
        # Keep only the last turns, so long chats do not get slow and expensive.
        messages = trim_history(messages, settings.max_turns)
        console.print(f"{settings.agent_name}> {reply}\n", style="cyan", markup=False)

    print("Bye!")


def main() -> None:
    load_dotenv()
    settings = load_settings()
    client = make_client(settings)
    chat_loop(client, settings)

בדיקת integration לצ'אט

chat_loop קוראת מהמקלדת ומדפיסה למסך. ל-pytest יש לזה fixtures: פרמטרים שמוסיפים לפונקציית הבדיקה לפי שם, ו-pytest מעביר אותם לבד. monkeypatch מחליף משהו זמנית, רק לבדיקה הזו. capsys תופס את כל מה שהודפס.

tests\test_cli.py
"""Integration tests: the whole chat loop, with the mock client."""

from agent.cli import chat_loop
from agent.config import Settings
from agent.llm import MockClient

SETTINGS = Settings(
    model="test-model", mock=True, agent_name="agent", max_turns=2, api_key=None
)


def type_lines(monkeypatch, *lines):
    """Make input() return these lines one by one, as if a user typed them."""
    answers = iter(lines)
    monkeypatch.setattr("builtins.input", lambda prompt: next(answers))


def test_a_short_conversation(monkeypatch, capsys):
    type_lines(monkeypatch, "hello", "how are you", "exit")
    chat_loop(MockClient(), SETTINGS)
    output = capsys.readouterr().out

לבדוק את ClaudeClient בלי לשלוח כלום

את ClaudeClient אי אפשר להחליף ב-MockClient, כי הוא עצמו מה שבודקים. אבל אפשר להחליף את מה שהוא משתמש בו: ה-SDK. בשביל זה יש לו הפרמטר sdk. כשמחלקה מקבלת את התלויות שלה מבחוץ במקום ליצור אותן בעצמה, קוראים לזה dependency injection, וזה מה שהופך קוד לניתן לבדיקה. את ה-SDK המזויף נותן unittest.mock.Mock, שמגיע עם Python: אובייקט שמקבל כל קריאה, זוכר אותה, ומחזיר מה שתגידו לו.

נסו לכתוב בדיקה ל-chat_loop כשה-API לא זמין. הלקוח המזויף יצטרך לזרוק anthropic.APIConnectionError, כי זה מה ש-cli.py תופס. כלומר הבדיקה של הצ'אט צריכה להכיר את החריגות הפנימיות של ה-SDK. וזו הבעיה עצמה: cli.py יודע איך anthropic נכשל, למרות שהוא לא אמור לדעת ש-anthropic קיים. תחליפו ספק, והצ'אט ישתנה.

tests\test_llm.py
def test_connection_error_becomes_llm_error():
    sdk = Mock()
    # The SDK raises this when it cannot reach the server. Any stand-in request will do.
    sdk.messages.create.side_effect = anthropic.APIConnectionError(request=Mock())
    client = ClaudeClient("test-model", "Be brief.", sdk=sdk)

    with pytest.raises(LLMError) as caught:
        client.reply([{"role": "user", "content": "hello"}])

    assert "Could not reach the API" in str(caught.value)
    assert not caught.value.fatal

הריצו את ארבעת הכלים (pytest, ruff check, ruff format, mypy agent), ושמרו עם "Turn API errors into LLMError at the client boundary". הכללים שמאחורי השינוי:

  • תופסים חריגה ספציפית, שיודעים מה לעשות איתה. אף פעם לא except: ריק או except Exception: pass. אלה בולעים גם באגים שלכם, כמו KeyError, והם נעלמים בלי עקבות. באג צריך להפיל את התוכנית, כדי שתראו אותו.
  • הסדר חשוב. AuthenticationError היא סוג של APIStatusError, ולכן היא באה לפניה. בתרגיל 5 תראו מה קורה אחרת.
  • raise ... from error שומר את החריגה המקורית בתוך החדשה (__cause__). המשתמש מקבל משפט ברור, ומי שחוקר מקבל את כל השרשרת.
  • מבדילים בין מה שאפשר לנסות שוב לבין מה שלא. רשת שנפלה עשויה לחזור, אז הצ'אט ממשיך. מפתח שגוי לא יתקן את עצמו, ולכן fatal=True והתוכנית יוצאת.

ביום הראשון בצוות לא תכתבו קוד, תקראו. וגם אחר כך, תקראו הרבה יותר משתכתבו. לקרוא קוד זר מהשורה הראשונה עד האחרונה לא עובד. זה הסדר שעובד:

  1. מתחילים מאיך מריצים: README.md, ואז נקודת הכניסה. אצלכם __main__.py, ומשם main.
  2. קוראים את הבדיקות. בדיקה טובה היא דוגמת שימוש עם התוצאה הצפויה. test_cli.py מסביר את הצ'אט מהר יותר מ-cli.py.
  3. עוקבים אחרי מסלול אחד, למשל "מה קורה כשלוחצים Enter". ב-VS Code, F12 (Go to Definition) קופץ למקום שבו שם מוגדר, Shift+F12 מראה איפה משתמשים בו, ו-Alt+← חוזר.
  4. שואלים את git למה. git log --oneline -- agent\history.py מראה את ההיסטוריה של קובץ, ו-git blame agent\history.py מראה איזה commit שינה כל שורה. הודעת commit טובה היא התשובה.
  5. מריצים ועוצרים. Breakpoint (פרק 1) מראה את הערכים האמיתיים, ולא את מה שניחשתם.

זה עובד גם על ספריות. הקוד של anthropic נמצא אצלכם, ב-.venv\Lib\site-packages\anthropic, ו-F12 על anthropic.AuthenticationError ב-llm.py לוקח אתכם אליו. כשהתיעוד לא עונה, הקוד תמיד עונה.

3.14מילון מונחים

package / module
תיקייה עם __init__.py / קובץ .py אחד. מהן מייבאים.
refactoring
שינוי של מבנה הקוד בלי לשנות את מה שהוא עושה.
test / assertion
פונקציה שמריצה קוד ובודקת תוצאה / התנאי שנבדק (assert).
unit / integration / e2e
בדיקה של יחידה אחת לבד / של כמה חלקים יחד / של כל המערכת האמיתית, כולל שירותים חיצוניים.
regression test
בדיקה ששומרת שבאג שתוקן לא יחזור.
fixture
משאב ש-pytest מכין לבדיקה לפי שם הפרמטר, כמו monkeypatch או capsys.
test double / mock
רכיב מזויף שעומד במקום רכיב אמיתי בבדיקה.
dependency injection
מחלקה מקבלת מבחוץ את מה שהיא תלויה בו, ולכן אפשר להחליף אותו.
TDD
כותבים בדיקה שנכשלת, ורק אז את הקוד שמעביר אותה.
linter / formatter
כלי שמוצא בעיות בקוד בלי להריץ אותו / כלי שמסדר את צורת הקוד.
type hint / type checker
סימון של סוג הערך הצפוי / כלי (mypy) שבודק שהקוד מסכים עם הסימונים.
dev dependency
חבילה שצריך רק בפיתוח, כמו pytest, ולא בזמן ריצה.
exception chaining

log level
חומרה של הודעת log: DEBUG, INFO, WARNING, ERROR.
