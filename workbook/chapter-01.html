סביבת העבודה

איך לוקחים קובץ .py שמישהו שלח לכם, וגורמים לו לרוץ אצלכם, אצל חבר, ובעוד שנה, בדיוק באותה צורה.

בסוף הפרק תדעו

  • לנוע בין תיקיות ולהריץ פקודות ב-terminal בלי לפחד ממנו.
  • להסביר מה זה virtual environment ולמה לכל פרויקט יש אחד משלו.
  • לנהל את החבילות של פרויקט עם uv, ולהבין מה התפקיד של pyproject.toml ושל uv.lock.
  • להעביר הגדרות וסודות לתוכנית דרך environment variables וקובץ .env.
  • לעצור תוכנית באמצע ריצה עם ה-debugger ולהסתכל מה יש במשתנים.

זמן משוער: שלוש עד ארבע שעות, כולל התרגילים. מה צריך: מחשב עם Windows 10 או 11 וחיבור לאינטרנט. לא צריך כרטיס אשראי, כי כל הפרק עובד גם במצב mock שאינו עולה כסף.

1.1הבעיה: "אצלי זה עובד"

אתם כבר יודעים לכתוב Python. כנראה כתבתם אותו ב-notebook, ב-Colab, או בסביבה שמישהו אחר הכין בשבילכם. הקוד רץ, ולא הייתם צריכים לשאול איפה הוא רץ ועם אילו חבילות.

עכשיו דמיינו שעמית שולח לכם קובץ אחד, chat.py, וכותב: "זה סוכן צ'אט קטן שעובד עם Claude, תריצו ותגידו מה דעתכם". אתם מריצים, ומקבלים את זה:

output

    import anthropic

אצל העמית הקוד עובד. אצלכם לא. הקוד זהה, ולכן ההבדל חייב להיות במשהו שנמצא מסביב לקוד. לדבר הזה קוראים סביבה (environment), והיא מורכבת מארבעה דברים:

הפרק הזה עובר על ארבעתם. בסופו chat.py ירוץ אצלכם, ויותר חשוב: תהיה לכם תיקייה שכל אדם אחר יכול לקחת ולהריץ בשתי פקודות. זו ההגדרה של פרויקט, להבדיל מקובץ.

הפרויקט שילווה אתכם בכל החוברת

הקובץ chat.py הוא נקודת ההתחלה של סוכן צ'אט שתבנו לאורך 21 הפרקים. היום הוא קובץ אחד שרץ ב-terminal. בהמשך הוא יקבל בדיקות, API, בסיס נתונים שזוכר שיחות, כלים שהוא יכול להפעיל, יפוצל לכמה שירותים שמדברים ביניהם, ובחלק האחרון יהפוך למערכת של כמה סוכנים שעובדים יחד. כל פרק מוסיף שכבה אחת, ורק אחרי שהרגשתם למה היא נחוצה.

1.3ה-terminal

ה-terminal הוא חלון שבו מקלידים פקודה, לוחצים Enter, ומקבלים תשובה בטקסט. כל הכלים שתפגשו בחוברת (git, uv, docker) מופעלים ממנו. גם שרתים בענן מנוהלים כך, כי אין להם מסך. לכן זה הכלי הראשון.

ב-Windows נשתמש ב-PowerShell. כדי לפתוח: לחצו על מקש Win, הקלידו terminal, ולחצו Enter. תראו שורה כזו:

PowerShell
PS C:\Users\you>

השורה הזו נקראת prompt. החלק C:\Users\you הוא תיקיית העבודה (working directory): המקום שבו אתם "עומדים" כרגע. כל פקודה שתריצו פועלת ביחס אליו. בדוגמאות בחוברת לא מקלידים את PS ...>, רק את מה שבא אחריו.

שש הפקודות שמספיקות ל-90% מהזמן

פקודהמה היא עושהדוגמה
pwdמדפיסה איפה אתם עומדיםpwd
lsמציגה את הקבצים והתיקיות כאןls

נתיבים: מוחלט ויחסי

נתיב מוחלט (absolute path) מתחיל מהכונן ונכון מכל מקום: C:\Users\you\projects\my-agent. נתיב יחסי (relative path) מתחיל מהמקום שבו אתם עומדים: אם אתם ב-C:\Users\you, אז projects\my-agent מוביל לאותה תיקייה.

שלושה קיצורים שכדאי לזכור: . היא התיקייה הנוכחית, .. היא התיקייה שמעליה, ו-~ היא תיקיית הבית שלכם (C:\Users\you).

PowerShell
cd ~              # go to your home folder
mkdir projects    # create a folder for all your code
cd projects
pwd               # C:\Users\you\projects
cd ..             # one level up, back to C:\Users\you
שני הרגלים שחוסכים המון הקלדה

מקש Tab משלים שמות של קבצים ותיקיות: הקלידו cd pro ולחצו Tab. מקש חץ למעלה ↑ מחזיר את הפקודה הקודמת, כך שאין צורך להקליד שוב פקודה שכבר הרצתם.

אל תשימו פרויקטים בתוך OneDrive

ב-Windows, התיקיות Desktop ו-Documents מסונכרנות לעיתים קרובות ל-OneDrive. פרויקט קוד מכיל אלפי קבצים קטנים שמשתנים כל הזמן, והסנכרון מאט אותו ולפעמים נועל קבצים. לכן עובדים בתיקייה C:\Users\you\projects, שאינה מסונכרנת.

1.4מתקינים את הכלים

צריך שלושה כלים. ב-Windows יש מנהל התקנות מובנה בשם winget, אז מתקינים את שלושתם מה-terminal:

PowerShell
winget install --id astral-sh.uv -e
winget install --id Git.Git -e
winget install --id Microsoft.VisualStudioCode -e
כלימה התפקיד שלומתי נשתמש

gitשומר היסטוריה של הקוד ומאפשר לעבוד עליו עם אחריםפרק 2

סגרו את חלון ה-terminal ופתחו חדש. חלון שהיה פתוח בזמן ההתקנה לא מכיר את הכלים החדשים. אחר כך ודאו שהכול הותקן:

PowerShell

git --version
code --version

כל פקודה צריכה להדפיס מספר גרסה. אם אחת מהן מחזירה "is not recognized", עברו לטבלת התקלות בסעיף 1.11.

ומה עם Python עצמו?

לא צריך להתקין אותו בנפרד. כש-uv צריך גרסת Python שאין במחשב, הוא מוריד אותה לבד. אם כבר יש לכם Python מותקן, זה בסדר גמור, uv ישתמש בו.

1.5דוגמה מודרכת: מקובץ לפרויקט

עכשיו עושים את זה ביחד, צעד אחרי צעד. הקלידו את הפקודות בעצמכם. המטרה של הסעיף היא שהידיים שלכם יכירו את התהליך.

1יוצרים תיקייה ומביאים את הקבצים

בתיקייה שבה נמצאת החוברת יש תיקייה בשם starter ובה שלושה קבצים. העתיקו אותם לתיקיית פרויקט חדשה. החליפו את הנתיב בשורה השלישית בנתיב שבו שמרתם את החוברת:

PowerShell
cd ~\projects
mkdir my-agent
cp C:\path\to\behind-the-code\starter\* my-agent
cd my-agent
ls

הפקודה ls צריכה להראות שלושה קבצים: chat.py, debug_me.py ו-.env.example.

2מריצים, ונכשלים

PowerShell
uv run python chat.py

תקבלו את השגיאה מתחילת הפרק: ModuleNotFoundError: No module named 'anthropic'. קראו אותה מלמטה למעלה, כמו כל traceback ב-Python: השורה האחרונה אומרת מה קרה (אין מודול כזה), והשורה שמעליה אומרת איפה (שורה 16, import anthropic).

anthropic היא חבילה חיצונית. היא לא חלק מ-Python, מישהו צריך להתקין אותה. השאלה היא איפה.

3למה לא פשוט pip install?

הדרך המוכרת היא pip install anthropic. זה מתקין את החבילה ב-Python הראשי של המחשב, והיא משותפת לכל הפרויקטים שלכם. זה עובד עד שיש שני פרויקטים:

  • פרויקט א' נכתב מול גרסה 1 של חבילה מסוימת.
  • פרויקט ב' צריך את גרסה 2 של אותה חבילה, שבה שינו שמות של פונקציות.

אפשר להתקין רק גרסה אחת במקום אחד, ולכן אחד הפרויקטים יישבר. הפתרון הוא לתת לכל פרויקט מקום משלו: תיקייה בשם .venv בתוך הפרויקט, שמכילה עותק של Python ואת החבילות של הפרויקט הזה בלבד. זה ה-virtual environment.

4הופכים את התיקייה לפרויקט

PowerShell
uv init --bare
output
Initialized project `my-agent`

נוצר קובץ אחד חדש, pyproject.toml. זו "תעודת הזהות" של הפרויקט. הציגו אותו עם cat pyproject.toml:

pyproject.toml
[project]
name = "my-agent"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = []

שימו לב לשתי שורות: requires-python קובעת איזו גרסת Python הפרויקט דורש (המספר אצלכם עשוי להיות שונה), ו-dependencies היא רשימת החבילות שהוא צריך. כרגע היא ריקה.

5מוסיפים את החבילות

הקוד מייבא שתי חבילות חיצוניות: anthropic (לדבר עם Claude) ו-dotenv (לקרוא קובץ .env, נגיע אליו מיד). שימו לב שהחבילה השנייה נקראת python-dotenv בהתקנה ו-dotenv ב-import. זה קורה לפעמים.

PowerShell
uv add anthropic python-dotenv
output (shortened)

פקודה אחת עשתה שלושה דברים. הריצו ls ותראו מה נוסף:

מה נוצר או השתנהמה יש בומי כותב אותו
pyproject.tomlשתי החבילות נוספו ל-dependencies, עם גרסה מינימלית: "anthropic>=2.10.0"אתם (דרך uv add)
uv.lockהגרסה המדויקת של כל חבילה שהותקנה, כולל חבילות שהחבילות שלכם צריכותרק uv. לא עורכים ביד
.venv\ה-virtual environment עצמו: Python והחבילות המותקנותרק uv. אפשר למחוק ולבנות מחדש

ביקשתם שתי חבילות והותקנו שבע-עשרה. הסיבה: anthropic עצמה צריכה חבילות אחרות כדי לעבוד, והן צריכות עוד חבילות. לאלה קוראים transitive dependencies, ו-uv מוצא ומתקין את כולן.

למה שני קבצים, pyproject.toml וגם uv.lock?

pyproject.toml אומר מה אתם רוצים: "anthropic, מגרסה 2.10.0 ומעלה". uv.lock מתעד מה קיבלתם בפועל: הגרסה המדויקת של כל אחת מהחבילות שהותקנו. מי שיבנה את הפרויקט מחר, או בעוד שנה, יקבל מה-lock file בדיוק את אותן גרסאות, גם אם בינתיים יצאו חדשות. כך נפתרת הבעיה של "אצלי זה עובד".

6מריצים שוב

PowerShell
uv run python chat.py
output
ANTHROPIC_API_KEY is not set.
Put it in a .env file, or set CHAT_MOCK=1 to run without a key.

התקדמנו: ה-import הצליח, והשגיאה עכשיו אחרת. התוכנית מחפשת משהו בשם ANTHROPIC_API_KEY ולא מוצאת. זה משתנה סביבה, והוא הנושא של הסעיף הבא.

ומה עושה uv run? הוא מריץ את הפקודה שאחריו בתוך ה-.venv של הפרויקט. בלי uv run, הפקודה python chat.py הייתה משתמשת ב-Python הראשי של המחשב, שבו החבילות לא מותקנות. לפני הריצה, uv run גם בודק שה-.venv תואם ל-uv.lock, ומתקן אותו אם לא.

1.6משתני סביבה וקובץ .env

פתחו את chat.py והסתכלו על השורות האלה:

chat.py
load_dotenv()

MODEL = os.getenv("CHAT_MODEL", "claude-opus-5-5")
MOCK = os.getenv("CHAT_MOCK", "0") == "1"

התוכנית לא מחליטה בעצמה עם איזה מודל לעבוד. היא שואלת את הסביבה: "יש משתנה בשם CHAT_MODEL? אם לא, אשתמש בברירת המחדל". משתנה סביבה (environment variable) הוא זוג של שם וערך, שנמצא מחוץ לקוד, וכל תוכנית שרצה יכולה לקרוא אותו.

למה לא לכתוב את הערכים בקוד?

  • סודות. מפתח API הוא כמו סיסמה לחשבון הבנק. הקוד ישותף עם אחרים ויעלה ל-GitHub. אם המפתח כתוב בקוד, הוא משותף יחד איתו. זו אחת הטעויות הנפוצות והיקרות ביותר של מתכנתים מתחילים.
  • אותו קוד, סביבות שונות. במחשב שלכם תרצו מצב mock. בשרת האמיתי תרצו מודל אמיתי ומפתח של החברה. הקוד נשאר זהה ורק הסביבה משתנה. תפגשו את הרעיון הזה שוב בפרק 10, על deployment.

דרך ראשונה: להגדיר ב-terminal

PowerShell
$env:CHAT_MOCK = "1"       # set a variable
$env:CHAT_MOCK             # print its value
uv run python chat.py

הפעם התוכנית עולה ואפשר לדבר איתה. הקלידו הודעה או שתיים, ואז exit:

output
Running in MOCK mode - answers are fake, nothing is sent to the API.
Type a message and press Enter. Type 'exit' to quit.

you> hello
agent> [mock reply, turn 1] You said: hello

you> exit
Bye!

החיסרון: משתנה שהוגדר כך חי רק בחלון ה-terminal הזה. סגרתם את החלון, והוא נעלם. כדי למחוק אותו בלי לסגור את החלון:

PowerShell
Remove-Item Env:CHAT_MOCK

דרך שנייה: קובץ .env

קובץ .env הוא קובץ טקסט פשוט בתיקיית הפרויקט, עם שורה לכל משתנה. הפונקציה load_dotenv() בתחילת chat.py קוראת אותו והופכת כל שורה למשתנה סביבה. בתיקייה יש כבר תבנית, .env.example. העתיקו אותה:

PowerShell
cp .env.example .env
cat .env
.env
# Your secret key from https://platform.claude.com (not needed in mock mode)
ANTHROPIC_API_KEY=

# Which Claude model to chat with
CHAT_MODEL=claude-opus-5-5

# 1 = fake answers, free, no key needed. 0 = real answers from the API.
CHAT_MOCK=1

הריצו שוב uv run python chat.py. התוכנית עולה במצב mock, בלי שהגדרתם דבר ב-terminal.

שני קבצים, שני תפקידים

.env מכיל את הערכים האמיתיים שלכם, כולל סודות. הוא פרטי: לא שולחים אותו לאף אחד, ולא מעלים אותו ל-git (בפרק 2 תלמדו איך מוודאים את זה). .env.example מכיל רק את שמות המשתנים, בלי ערכים סודיים. הוא משותף, והתפקיד שלו לספר למי שמקבל את הפרויקט אילו משתנים צריך להגדיר.

רוצים תשובות אמיתיות? (רשות)

כל החוברת אפשרית במצב mock. אם תרצו לדבר עם Claude אמיתי, צריך מפתח API, והשימוש עולה כסף לפי כמות הטקסט. לשיחות הקצרות של החוברת מדובר בסכומים קטנים.

  1. היכנסו ל-platform.claude.com, פתחו חשבון והוסיפו אמצעי תשלום.
  2. צרו מפתח בעמוד API Keys והעתיקו אותו. הוא מוצג פעם אחת בלבד.
  3. פתחו את .env, הדביקו את המפתח אחרי ANTHROPIC_API_KEY=, ושנו את CHAT_MOCK ל-0.

כדי להוזיל, אפשר לשנות את CHAT_MODEL בקובץ .env למודל קטן וזול יותר, למשל claude-haiku-5-5. שימו לב שלא נגעתם בקוד כדי להחליף מודל. זה בדיוק היתרון של משתני סביבה.

1.7מבנה הפרויקט

כך נראית התיקייה שלכם עכשיו. לכל קובץ יש תפקיד, וחשוב לדעת אילו מהם משתפים עם אחרים ואילו לא:

קובץ או תיקייהתפקידמשתפים?
chat.pyהקודכן
debug_me.pyקובץ לתרגיל 5כן
pyproject.tomlשם הפרויקט, גרסת Python, רשימת החבילותכן
uv.lockהגרסאות המדויקות של כל החבילותכן

הכלל שמאחורי הטבלה: משתפים את ההוראות לבניית הסביבה, ולא את הסביבה עצמה. התיקייה .venv גדולה, תלויה במערכת ההפעלה, וניתנת לשחזור מלא בפקודה אחת (uv sync). אין סיבה לשלוח אותה.

1.8ה-IDE וה-debugger

עד עכשיו עבדתם ב-terminal. לכתיבת קוד משתמשים ב-IDE, עורך שמבין את הקוד. פתחו את הפרויקט ב-VS Code מתוך התיקייה שלו:

PowerShell
code .

הנקודה אומרת "פתח את התיקייה הנוכחית". תמיד פותחים את התיקייה של הפרויקט ולא קובץ בודד, כדי ש-VS Code יזהה את ה-.venv.

הכנה חד-פעמית

  1. התקינו את התוסף של Python: לחצו Ctrl+Shift+X, חפשו Python, והתקינו את התוסף של Microsoft.
  2. בחרו את ה-interpreter של הפרויקט: לחצו Ctrl+Shift+P, הקלידו Python: Select Interpreter, ובחרו בשורה שמכילה .venv.
  3. פתחו terminal בתוך VS Code עם Ctrl+`. הוא נפתח ישר בתיקיית הפרויקט.

מה זה debugger ולמה לא מספיק print

כשקוד לא עושה מה שציפיתם, האינסטינקט הוא להוסיף print בכל מקום. זה עובד, אבל לאט: צריך לנחש מראש מה להדפיס, להריץ, ולנחש שוב. debugger עוצר את התוכנית באמצע הריצה, בשורה שבחרתם, ומראה את כל המשתנים באותו רגע. משם אפשר להתקדם שורה אחרי שורה ולראות מה משתנה.

נסו עכשיו

  1. פתחו את chat.py ומצאו את השורה messages.append({"role": "assistant", "content": reply}).
  2. לחצו בשוליים, משמאל למספר השורה. מופיעה נקודה אדומה. זו breakpoint: בקשה לעצור כאן.
  3. לחצו F5 ובחרו Python Debugger ואז Python File.
  4. התוכנית עולה ב-terminal שבתחתית. הקלידו הודעה ולחצו Enter.
  5. הריצה נעצרת על השורה שסימנתם. בצד מופיעה חלונית Variables. פתחו בה את messages והסתכלו מה יש בפנים.
מקששםמה הוא עושה
F5Continueממשיך לרוץ עד ה-breakpoint הבאה
F10Step Overמריץ את השורה הנוכחית ועוצר בשורה הבאה
F11Step Intoאם השורה קוראת לפונקציה, נכנס לתוכה
Shift+F5Stopמפסיק את התוכנית
מה שתראו ב-messages הוא הזיכרון של הסוכן

הרשימה מכילה את כל השיחה: הודעה עם role של user, אחריה הודעה עם role של assistant, וחוזר חלילה. בכל תור, chat.py שולח ל-API את כל הרשימה, כי ה-API עצמו אינו זוכר דבר בין בקשה לבקשה. סגרתם את התוכנית, והרשימה נמחקת. את הבעיה הזו תפתרו בפרק 6, עם בסיס נתונים.

1.9תרגילים

התרגילים מסודרים מהמודרך אל הפתוח. עשו אותם לפי הסדר, כי כל אחד נשען על הקודם. סמנו כל תרגיל שסיימתם, והסימון יישמר בדפדפן הזה. לשאלות הכתובות יש מקום לתשובה, שגם הוא נשמר. פתרונות מלאים נמצאים בדף נפרד. פתחו אותו רק אחרי שניסיתם באמת.

תרגיל 1 · ניווט בלי עכבר

מודרך

בצעו את כל המשימות מה-terminal בלבד, בלי סייר הקבצים:

  1. עברו לתיקיית הבית, ומשם ל-projects.
  2. צרו תיקייה בשם playground ובתוכה תיקייה בשם notes.
  3. היכנסו ל-notes והדפיסו את הנתיב המלא שלה.
  4. מתוך notes, בפקודה אחת ובנתיב יחסי, הציגו את תוכן הקובץ chat.py שנמצא ב-my-agent.
  5. חזרו ל-my-agent בפקודת cd אחת.

תרגיל 2 · להרוס ולבנות מחדש

מודרך

התרגיל הזה מוכיח לכם ש-.venv היא תוצר שאפשר לשחזר, ולא משהו שצריך לשמור עליו.

  1. מחקו את ה-virtual environment: Remove-Item -Recurse -Force .venv
  2. ודאו עם ls שהיא נעלמה.
  3. בנו אותה מחדש: uv sync
  4. הריצו את chat.py וודאו שהוא עובד כמו קודם.

תרגיל 3 · משתנה סביבה משלכם

בינוני

כרגע התשובות מודפסות אחרי agent>. תנו לסוכן שם שאפשר לשנות בלי לגעת בקוד.

  1. ב-chat.py, הוסיפו קבוע בשם AGENT_NAME שנקרא ממשתנה סביבה באותו שם. ברירת המחדל היא agent.
  2. השתמשו בו בשורה שמדפיסה את התשובה.
  3. הוסיפו את המשתנה לקובץ .env עם שם שבחרתם, והריצו.
  4. הוסיפו אותו גם ל-.env.example, עם הערה קצרה שמסבירה מה הוא. חשבו: למה צריך לעדכן גם את הקובץ הזה?
  5. ניסוי: בלי לשנות את .env, הגדירו ב-terminal ערך אחר: $env:AGENT_NAME = "shell", והריצו שוב.

בסיום, מחקו את המשתנה מה-terminal: Remove-Item Env:AGENT_NAME

תרגיל 4 · להוסיף חבילה

בינוני

החבילה rich מדפיסה טקסט צבעוני ל-terminal. השתמשו בה כדי שהתשובות של הסוכן יופיעו בצבע.

  1. לפני שמתחילים, הציצו ב-pyproject.toml וזכרו איך נראית הרשימה dependencies.
  2. הוסיפו את החבילה: uv add rich. שימו לב כמה חבילות הותקנו.
  3. ב-chat.py, הוסיפו בראש הקובץ from rich.console import Console, וצרו אובייקט אחד: console = Console().
  4. החליפו את ה-print של התשובה בשורה הזו:
chat.py
console.print(f"{AGENT_NAME}> {reply}\n", style="cyan", markup=False)

תרגיל 5 · ציד באגים עם ה-debugger

בינוני

שיחות ארוכות עולות יותר כסף, ולכן סוכנים רבים שומרים רק את התורות האחרונים. בקובץ debug_me.py יש פונקציה שאמורה לעשות את זה, ויש בה באג. הריצו אותה:

PowerShell
uv run python debug_me.py
output
Expected: 6 messages, the first one from 'user'
Got:      3 messages, the first one from 'assistant'

הכלל של התרגיל: אסור להוסיף print, ואסור לתקן לפני שראיתם את הבעיה בעיניים.

  1. שימו breakpoint על השורה הראשונה בתוך trim_history והריצו עם F5.
  2. בחלונית Variables, בדקו כמה איברים יש ב-messages ומה הערך של max_turns.
  3. התקדמו עם F10 עד שורת ה-return.
  4. בתחתית המסך יש לשונית Debug Console. הקלידו בה את הביטוי שמופיע אחרי ה-return ובדקו מה הוא מחזיר. נסו שם גם ביטויים אחרים, עד שתמצאו אחד שמחזיר את התוצאה הנכונה.
  5. תקנו את הקוד והריצו שוב.

תרגיל 6 · מבחן החבר

פתוח

פרויקט טוב הוא פרויקט שאדם אחר מצליח להריץ בלי לשאול אתכם שאלות. כתבו קובץ README.md בתיקיית הפרויקט (באנגלית, כמקובל), שמסביר בקצרה:

  • מה הפרויקט עושה, במשפט או שניים.
  • מה צריך להיות מותקן במחשב.
  • אילו פקודות מריצים, לפי הסדר, כדי להגיע לשיחה ראשונה עם הסוכן.
  • אילו משתני סביבה קיימים ומה כל אחד עושה.

עכשיו בדקו את עצמכם. צרו תיקייה חדשה, ~\projects\friend-test, והעתיקו אליה רק את הקבצים שסימנתם בסעיף 1.7 כ"משתפים". בלי .venv ובלי .env. אחר כך בצעו את ההוראות שכתבתם ב-README.md, מילה במילה, בלי להוסיף שום דבר מהזיכרון.

1.10בדקו את עצמכם

סמנו רק מה שאתם מסוגלים להסביר בקול רם לאדם אחר, בלי להציץ בפרק. מה שלא סימנתם הוא מה שכדאי לקרוא שוב.

1.12מילון מונחים

terminal
חלון שבו מפעילים תוכנות בהקלדת פקודות.
PowerShell
שפת הפקודות שרצה בתוך ה-terminal ב-Windows.
working directory
התיקייה שבה ה-terminal "עומד" כרגע. נתיבים יחסיים נמדדים ממנה.
interpreter
התוכנה שקוראת קוד Python ומריצה אותו.
package
ספריית קוד שמישהו אחר כתב ואפשר להתקין ולהשתמש בה.
dependency
חבילה שהפרויקט שלכם צריך כדי לעבוד.
virtual environment
תיקייה (.venv) עם Python וחבילות ששייכים לפרויקט אחד בלבד.
lock file
קובץ (uv.lock) שמתעד את הגרסה המדויקת של כל חבילה, כדי שכולם יקבלו אותה סביבה.
environment variable
זוג של שם וערך שנמצא מחוץ לקוד, והתוכנית קוראת אותו בזמן ריצה.
API key
מחרוזת סודית שמזהה אתכם מול שירות חיצוני. מתנהגים איתה כמו עם סיסמה.
mock
תחליף מזויף לרכיב אמיתי, שמאפשר להריץ ולבדוק קוד בלי תלות בו.
IDE
עורך קוד שכולל גם כלים להרצה, לניווט ול-debugging.
breakpoint
סימון על שורה, שמורה ל-debugger לעצור כשהריצה מגיעה אליה.
traceback
הדוח ש-Python מדפיס כשיש שגיאה. קוראים אותו מלמטה למעלה.

1.13מה הלאה

יש לכם פרויקט שרץ, ושכל אחד יכול לבנות מחדש. אבל שימו לב מה קרה בתרגילים: שיניתם את chat.py כמה פעמים, ואין לכם דרך לחזור לגרסה שעבדה לפני שעה. אם תשלחו את התיקייה לחבר והוא ישנה משהו, לא תדעו מה השתנה, ולא תוכלו לאחד את השינויים שלו עם שלכם. ועדיין לא ברור מה מונע מהקובץ .env להישלח בטעות יחד עם השאר.

שלוש הבעיות האלה הן הנושא של פרק 2: Git ו-GitHub.
