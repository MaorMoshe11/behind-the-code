5.1הבעיה: סוכן שרק אתם יכולים לדבר איתו

חברה שבונה אתר שואלת: "אפשר לשים את הסוכן שלך באתר שלי?". היום התשובה היא לא. הסוכן הוא לולאה שקוראת input() ומדפיסה ל-terminal. כדי לדבר איתו מתוכנית אחרת, היא הייתה צריכה לייבא את agent.cli ולזייף הקלדה, כמו שהבדיקות בפרק 3 עושות עם monkeypatch. ומי שאינו כותב Python בכלל לא יכול לדבר איתו.

ויש עוד שתי בעיות שאתם כבר מכירים. עברית ב-terminal מתהפכת (הבטחנו בפרק 1 ממשק שבו היא עובדת). ובסוף פרק 4 ראיתם שרת שמחליט מה לענות עם if על ה-path: עשרה paths, בדיקת קלט ומפתח יהפכו אותו לגוש שאי אפשר לתחזק.

הפתרון לשלושתן הוא אותו דבר: לתת לסוכן API (Application Programming Interface), דלת שתוכניות אחרות נכנסות בה. בפרק 4 הייתם ה-client של ה-API של Anthropic. בפרק הזה תהיו ה-server.

5.3מה זה API, ומה זה REST

API הוא חוזה: לאיזו כתובת שולחים, מה שולחים, ומה מקבלים בחזרה, כולל מה קורה כשמשהו לא בסדר. מי שקורא ל-API שלכם לא רואה את הקוד שלכם, ולא אמור לראות. הוא סומך על החוזה. לכן הכלל הראשון: מותר לשנות כל דבר מאחורי החוזה, ואסור לשבור את החוזה עצמו בלי להודיע. שדה שנעלם מתשובה שובר את כל מי שקרא אותו.

REST הוא הסגנון הנפוץ לחוזים כאלה מעל HTTP. הוא לא תקן עם חוקים מדויקים, אלא כמה הרגלים:

  • ה-URL הוא שם עצם, משאב (resource): /conversations/42, ולא /getConversation?id=42.
  • ה-method הוא הפועל: GET קורא, POST יוצר או שולח, DELETE מוחק (הטבלה מסעיף 4.5).
  • ה-status code אומר מה קרה, וה-body ב-JSON מוסיף פרטים.
  • כל בקשה עומדת בפני עצמה (stateless): השרת לא זוכר "מי דיבר איתי קודם". מה שצריך, הבקשה מביאה איתה.

הנקודה האחרונה חשובה לסוכן. ב-terminal יש שיחה אחת, והיא חיה במשתנה. בשרת מדברים איתו הרבה לקוחות בבת אחת, ולכן לכל שיחה יש מזהה (conversation_id), והלקוח שולח אותו בכל הודעה. זה החוזה שתבנו:

Endpointמה הוא עושהתשובות אפשריות

שני קודים חדשים כאן. 422 Unprocessable Entity: ה-JSON תקין, אבל התוכן לא מתאים לחוזה (שדה חסר, הודעה ריקה). 502 Bad Gateway: השרת שלכם בסדר, אבל שירות שהוא תלוי בו, כאן Claude, נכשל. ההבחנה עוזרת למי שקורא: 4xx תקנו את הבקשה, 502 לא אתם ולא אנחנו, נסו שוב בעוד רגע.

היום הרשימה messages חיה בתוך chat_loop. שרת לא יכול להשתמש בלולאה שקוראת input(), ולכן קודם מוציאים את השיחה למודול משלה. זה refactoring: שינוי מבנה בלי שינוי התנהגות, והבדיקות מפרק 3 הן שיגידו אם הצלחתם. ענף חדש:

"""The core of the agent: conversations and their messages.

The terminal chat and the HTTP API both use this module, so they behave the same.
Everything lives in memory: when the process stops, every conversation is gone.
"""

import logging
import uuid

from anthropic.types import MessageParam

from agent.history import trim_history
from agent.llm import ChatClient, LLMError

log = logging.getLogger(__name__)


class ConversationNotFound(Exception):
    """No conversation has this id (maybe the server restarted)."""


class Conversations:
    """Every open conversation, by id, and the one way to add a message to it."""

    def __init__(self, client: ChatClient, max_turns: int) -> None:
        self.client = client
        self.max_turns = max_turns
        self._messages: dict[str, list[MessageParam]] = {}

    def start(self) -> str:
        """Open a new, empty conversation and return its id."""
        conversation_id = uuid.uuid4().hex
        self._messages[conversation_id] = []
        return conversation_id

    def messages(self, conversation_id: str) -> list[MessageParam]:
        """The messages the agent still remembers in this conversation."""
        if conversation_id not in self._messages:
            raise ConversationNotFound(conversation_id)
        return self._messages[conversation_id]

    def send(self, conversation_id: str, text: str) -> str:
        """Add the user's message, get the model's reply, and remember both."""
        messages = self.messages(conversation_id)
        messages.append({"role": "user", "content": text})
        log.info("sending %d messages", len(messages))
        try:
            reply = self.client.reply(messages)
        except LLMError:
            messages.pop()  # forget the message that got no answer
            raise
        messages.append({"role": "assistant", "content": reply})
        # Keep only the last turns, so long chats do not get slow and expensive.
        self._messages[conversation_id] = trim_history(messages, self.max_turns)
        return reply

    def reset(self, conversation_id: str) -> None:
        """Forget every message in this conversation, but keep the conversation."""
        self.messages(conversation_id).clear()

הקוד של send מוכר: הוא עבר כמעט כמו שהוא מ-chat_loop. מה שחדש הוא המילון _messages, ממזהה לרשימה, והמזהה עצמו: uuid4().hex הוא 32 תווים אקראיים, כך שאי אפשר לנחש מזהה של שיחה של מישהו אחר. ב-cli.py, מחקו את הייבוא של MessageParam ושל trim_history, ייבאו את Conversations, והחליפו את גוף הלולאה:

5.6Schemas עם Pydantic: POST /chat

ב-echo_server.py קראתם את ה-body עם json.loads וקיוויתם לטוב. מה אם חסר שדה? מה אם message הוא מספר? כל endpoint היה צריך לבדוק את זה ביד. ב-FastAPI מתארים את הצורה פעם אחת, כ-schema: מחלקה של Pydantic, עם type hints מפרק 3. החליפו את api.py בגרסה הזו:

agent\api.py
"""The agent as an HTTP service.

Run it with: uv run uvicorn agent.api:create_app --factory
"""

import logging

from dotenv import load_dotenv
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, Field

from agent.cli import setup_logging
from agent.config import SYSTEM_PROMPT, ConfigError, Settings, load_settings
from agent.conversations import ConversationNotFound, Conversations
from agent.llm import ChatClient, ClaudeClient, LLMError, MockClient

log = logging.getLogger(__name__)


class ChatRequest(BaseModel):
    """What a client sends to POST /chat."""

    message: str = Field(min_length=1, max_length=4000)
    conversation_id: str | None = Field(
        default=None, description="Leave it out to start a new conversation."
    )


class ChatResponse(BaseModel):
    """What POST /chat sends back."""

    conversation_id: str
    reply: str
    turns: int = Field(description="How many turns the agent remembers in this conversation.")


def make_client(settings: Settings) -> ChatClient:
    """The mock or the real client. A server cannot ask questions, so it refuses to start."""
    if settings.mock:
        return MockClient()
    if not settings.api_key:
        raise ConfigError("ANTHROPIC_API_KEY is not set (or set CHAT_MOCK=1).")
    return ClaudeClient(settings.model, SYSTEM_PROMPT)


def create_app(settings: Settings | None = None, client: ChatClient | None = None) -> FastAPI:
    """Build the app. uvicorn calls it with nothing; tests pass their own settings and client."""
    if settings is None:
        load_dotenv()
        settings = load_settings()
        setup_logging(settings.log_level)
    conversations = Conversations(client or make_client(settings), settings.max_turns)
    app = FastAPI(title="my-agent", version="0.5.0")

    @app.get("/health")
    def health() -> dict[str, str]:
        """Is the service up? Used by people and by monitoring."""
        return {"status": "ok"}

    @app.post("/chat")
    def chat(request: ChatRequest) -> ChatResponse:
        """Send one message. The reply comes back with the conversation's id."""
        conversation_id = request.conversation_id or conversations.start()
        try:
            reply = conversations.send(conversation_id, request.message)
        except ConversationNotFound:
            raise HTTPException(status_code=404, detail="No conversation with this id.") from None
        except LLMError as error:
            log.exception("request failed")
            raise HTTPException(status_code=502, detail=str(error)) from error
        turns = len(conversations.messages(conversation_id)) // 2
        return ChatResponse(conversation_id=conversation_id, reply=reply, turns=turns)

    return app

השורה המסומנת האחרונה עושה שלושה דברים. הפרמטר request: ChatRequest אומר ל-FastAPI: קרא את ה-body כ-JSON, ובדוק שהוא מתאים ל-ChatRequest. אם לא, הפונקציה לא נקראת בכלל, והלקוח מקבל 422 עם פירוט. וה--> ChatResponse אומר מה יוצא: FastAPI מוודא שהתשובה בצורה הזו, ולא שולח שדות שלא הוגדרו בה. החריגות של הליבה הופכות ל-status codes מהחוזה, וזה כל מה ש-api.py עושה: מתרגם בין HTTP לבין הליבה.

שני דברים נוספים. make_client לא שואל ולא מדפיס כמו בגרסה של ה-CLI: לשרת אין מי שיענה, ולכן הגדרה חסרה עוצרת אותו מיד, בעלייה, ולא בבקשה הראשונה של לקוח. ו-def chat היא פונקציה רגילה ולא async: FastAPI מריץ אותה ב-thread נפרד, כך ששאלה איטית ל-Claude לא תוקעת את כל שאר הלקוחות.

צרו תיקייה examples, ובה (ב-VS Code, כמו בתרגיל 5 בפרק 4) שני קבצים: chat-hello.json עם {"message": "hello"}, ו-chat-typo.json עם {"mesage": "hello"}, טעות כתיב בכוונה. הפעילו מחדש את השרת, ושלחו:

5.7Swagger ו-OpenAPI: ה-API מתאר את עצמו

פתחו בדפדפן http://127.0.0.1:8000/openapi.json. זה תיאור מלא של ה-API שלכם, שנוצר מהקוד: כל path, כל method, ה-schemas כולל minLength: 1 ו-maxLength: 4000, ואפילו ה-docstrings כתיאורים. הפורמט נקרא OpenAPI, והוא תקן: יש כלים שמייצרים ממנו client בכל שפה, ובדיקות שמוודאות שהחוזה לא נשבר.

עכשיו http://127.0.0.1:8000/docs. זה Swagger UI, דף שנבנה מאותו קובץ: כל endpoint בשורה, ולחיצה על Try it out שולחת בקשה אמיתית לשרת שלכם, ומראה את התשובה ואת פקודת ה-curl המקבילה. זו הדרך הנוחה לנסות API, וגם לשלוח עברית בלי להיאבק במירכאות של PowerShell. תעשו סיור מלא בתרגיל 1.

תיעוד שלא יכול לשקר

תיעוד שנכתב ביד מתיישן ביום שמישהו משנה את הקוד ושוכח את המסמך. /docs נבנה מהקוד בכל הפעלה, ולכן תמיד נכון. דף ה-Swagger עצמו טוען את העיצוב שלו מאתר חיצוני (CDN), ולכן בלי אינטרנט הוא יוצא ריק. /openapi.json עובד תמיד.

5.8אימות: מי מדבר איתי?

ברגע שהשרת מדבר עם Claude אמיתי, כל בקשה עולה לכם כסף. כרגע כל מי שמגיע ל-port יכול לשלוח בקשות. אימות (authentication) הוא התשובה לשאלה "מי אתה", והרשאה (authorization) לשאלה "מה מותר לך". בפרק 4 ראיתם את שתיהן בקודים: 401 לא ברור מי אתם, 403 ברור, ואסור.

הדרך הפשוטה, ומה ש-Anthropic עושה מולכם: מחרוזת סודית ארוכה, שהלקוח שולח ב-header בכל בקשה. צרו אחת:

agent\api.py (the additions)
# Clients prove who they are with this header. auto_error=False: we write the 401 ourselves.
api_key_header = APIKeyHeader(name="X-API-Key", auto_error=False)


def key_checker(expected: str) -> Callable[[str | None], None]:
    """Build the dependency that guards an endpoint: no key, or a wrong key, gets 401."""

    def check(key: Annotated[str | None, Depends(api_key_header)]) -> None:
        # compare_digest takes the same time for every wrong key, so timing reveals nothing.
        if key is None or not secrets.compare_digest(key, expected):
            raise HTTPException(status_code=401, detail="Missing or wrong X-API-Key header.")

    return check

# in create_app, after the settings are loaded:
    if not settings.agent_api_key:
        # Fail closed: a server without a key would let anyone spend your API credit.
        raise ConfigError("AGENT_API_KEY is not set. Put a long random value in .env.")
    conversations = Conversations(client or make_client(settings), settings.max_turns)
    require_key = Depends(key_checker(settings.agent_api_key))
    ...
    @app.post("/chat", dependencies=[require_key])

check היא dependency: פונקציה ש-FastAPI מריץ לפני ה-endpoint. אם היא זורקת 401, ה-endpoint לא רץ. כך הבדיקה כתובה פעם אחת, וכל endpoint שצריך הגנה מוסיף dependencies=[require_key]. /health נשאר פתוח בכוונה. ושימו לב ל"fail closed": בלי מפתח בהגדרות, השרת לא עולה. האלטרנטיבה, "אין מפתח, אז אין בדיקה", היא הדרך שבה שרתים נשארים פתוחים לעולם בטעות. הפעילו מחדש ושלחו בלי מפתח, ואז עם:

Webhooks: ה-API שקורא לכם

נניח שהסוכן היה מחכה לאישור תשלום משירות חיצוני. אפשר לשאול אותו כל דקה "נו, אושר?" (polling): בזבזני, ותמיד באיחור. ההפך הוא webhook: נותנים לשירות URL שלכם, והוא שולח אליו POST ברגע שמשהו קורה. כלומר אתם כותבים endpoint, והשירות האחר הוא ה-client. ארבעה דברים שכל מי שמקבל webhooks צריך לדעת:

  • כל אחד יכול לשלוח POST לכתובת שלכם. לכן השולח חותם על ה-body בסוד משותף (HMAC), ושולח את החתימה ב-header. אתם מחשבים אותה מחדש ומשווים, עם hmac.compare_digest, בדיוק כמו המפתח בסעיף 5.8.
  • עונים מהר, עם 2xx. עבודה ארוכה עושים אחר כך (פרק 12). שולח שלא קיבל תשובה בזמן מניח שנכשלתם.
  • אותו אירוע עלול להגיע פעמיים, כי השולח מנסה שוב. לכל אירוע יש מזהה, ומי שכבר טיפל בו מתעלם (idempotency, פרק 11).
  • צריך כתובת שהשולח מגיע אליה. 127.0.0.1 לא מספיק, ולכן webhooks מגיעים לשרתים אמיתיים (פרק 10).

5.11תרגילים

כל התרגילים על הענף feature/api. בתרגילים שמשנים קוד, הריצו בסוף את ארבעת הכלים ו-commit. השרת על 8000, ואחרי כל שינוי מפעילים אותו מחדש. פתרונות, כולל הפלטים, נמצאים בדף נפרד.

תרגיל 1 · סיור ב-Swagger

מודרך
  1. פתחו את /docs. לחצו Authorize והזינו את המפתח.
  2. ב-POST /chat, Try it out, ושלחו הודעה בעברית. העתיקו את conversation_id מהתשובה ושלחו הודעה שנייה איתו.
  3. מצאו את פקודת ה-curl ש-Swagger מציג, ואת ה-schemas בתחתית הדף.

תרגיל 2 · טבלת status codes

מודרך

גרמו לשרת להחזיר כל אחד מהקודים האלה, עם curl.exe או ב-/docs, ורשמו לכל אחד את הבקשה ואת ה-detail: 200, 401, 404 (שתי דרכים שונות), 405, 422 ו-502. רמז ל-502: הפעילו את השרת במצב אמיתי עם מפתח מזויף ו-ANTHROPIC_BASE_URL של http://127.0.0.1:9, כמו בתרגיל 3 בפרק 4, ונקו את המשתנים בסוף.

תרגיל 3 · GET /conversations/{id}

בינוני

הוסיפו endpoint שמחזיר את ההודעות שהסוכן זוכר בשיחה. הגדירו שני schemas: Message עם role (רק "user" או "assistant", רמז: Literal) ו-content, ו-ConversationOut עם conversation_id ו-messages: list[Message]. ה-path הוא "/conversations/{conversation_id}", ו-FastAPI מעביר את החלק שבסוגריים לפרמטר באותו שם. דרשו מפתח, והחזירו 404 למזהה לא קיים. כתבו שלוש בדיקות: שיחה קיימת, מזהה לא קיים, ובלי מפתח. Commit: "Add GET /conversations/{id}".

תרגיל 4 · DELETE /conversations/{id}

בינוני

ה-/reset של ה-API. הוסיפו ל-Conversations מתודה delete, ו-endpoint שמחזיר 204 No Content (רמז: status_code=204 ב-decorator, והפונקציה מחזירה None). בדיקה: אחרי מחיקה, GET על אותו מזהה מחזיר 404. ומה מחזירה מחיקה שנייה? הוסיפו את זה לבדיקה. Commit: "Add DELETE /conversations/{id}".

תרגיל 5 · scripts\ask.py: client משלכם

בינוני

כתבו סקריפט שמקבל הודעה (ו---conversation אופציונלי), שולח אותה ל-POST /chat, ומדפיס את התשובה ואת המזהה. השתמשו רק בספרייה הסטנדרטית: urllib.request ו-json. המפתח מ-AGENT_API_KEY (עם load_dotenv), הכתובת מ-AGENT_URL עם ברירת מחדל. ממשו את ההרגלים מסעיף 5.9: timeout, והודעה ברורה ושונה כשהשרת לא רץ (URLError) וכשהוא ענה בשגיאה (HTTPError, עם ה-detail). בדקו את שלושת המקרים, ו-commit.

תרגיל 6 · דף שלא שוכח (עד כמה שאפשר)

פתוח

היום, רענון של הדף מתחיל שיחה חדשה, והפעלה מחדש של השרת נותנת שגיאה 404 מבלבלת. שפרו את הדף: אחרי רענון הוא ממשיך את אותה שיחה ומציג את ההודעות שלה (רמז: sessionStorage, ו-GET /conversations/{id} מתרגיל 3), וכשהשרת כבר לא מכיר את השיחה, הוא אומר למשתמש מה קרה במילים פשוטות ומתחיל שיחה חדשה. בדקו את שני המקרים בדפדפן. בסוף, עדכנו את README.md (איך מריצים את השרת, ה-endpoints, AGENT_API_KEY ו-AGENT_URL בטבלת המשתנים, הקבצים החדשים), commit, ואחדו: git switch main, git merge feature/api, git push, git branch -d feature/api.

5.14מילון מונחים

API
חוזה שבו תוכנית אחת מדברת עם אחרת: כתובות, קלט, פלט ושגיאות.
REST
סגנון ל-APIs מעל HTTP: משאבים ב-URL, פעולות ב-method, תוצאות ב-status code.
endpoint
צירוף של method ו-path שה-API עונה עליו, כמו POST /chat.
stateless
כל בקשה מביאה איתה את כל מה שצריך. השרת לא זוכר את הבקשה הקודמת.
ASGI server
התוכנית שמאזינה ל-port ומעבירה בקשות לאפליקציה Python. כאן: uvicorn.
schema
תיאור של צורת הנתונים: אילו שדות, מאיזה סוג, באילו מגבלות.
OpenAPI
פורמט תקני לתיאור API. FastAPI מייצר אותו ב-/openapi.json.
Swagger UI
דף שנבנה מתיאור OpenAPI, ומאפשר לנסות כל endpoint.
authentication / authorization
מי אתם / מה מותר לכם.
API key
מחרוזת סודית ארוכת-טווח שמזהה תוכנית לקוח.
JWT
token חתום שמכיל פרטים קריאים (מי, עד מתי). החתימה מונעת שינוי, לא קריאה.
dependency
ב-FastAPI: פונקציה שרצה לפני endpoint, למשל בדיקת מפתח.
webhook
endpoint שלכם ששירות אחר קורא לו כשמשהו קורה אצלו.
HMAC
חתימה על הודעה בעזרת סוד משותף. מוכיחה מי שלח ושלא שינו אותה.

5.15מה הלאה

לסוכן יש עכשיו API עם חוזה, מפתח, תיעוד ובדיקות, ודף שבו עברית נראית נכון. אבל ראיתם בצעד 4 ובתרגיל 6 את החולשה: כל השיחות חיות במילון אחד, בזיכרון של תהליך אחד. הפעלה מחדש, עדכון גרסה או קריסה, וכולן נעלמות, לכל המשתמשים. ואם תרצו להריץ שני תהליכים של השרת כדי לשרת יותר משתמשים, כל אחד מהם יכיר רק חצי מהשיחות.

הפתרון הוא לשמור את השיחות מחוץ לתהליך, במקום שנועד בדיוק לזה. בפרק 6: בסיסי נתונים, Conversations יקבל מימוש שכותב ל-SQLite, וה-conversation_id שכבר נמצא בכל בקשה ותשובה יהיה המפתח של הטבלה. ה-API, הדף וה-CLI לא ישתנו, וזו בדיוק הסיבה שהפרדתם ביניהם.
