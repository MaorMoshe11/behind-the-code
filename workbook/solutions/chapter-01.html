פרק 1 · סביבת העבודה

קראו פתרון רק אחרי שניסיתם את התרגיל בעצמכם. מי שנתקע ומציץ לומד פחות ממי שנתקע עשר דקות ואז מצליח.

1ניווט בלי עכבר

PowerShell
cd ~\projects
mkdir playground\notes        # creates both folders at once
cd playground\notes
pwd                           # C:\Users\you\projects\playground\notes
cat ..\..\my-agent\chat.py    # task 4
cd ..\..\my-agent             # task 5

במשימה 4, כל .. עולה רמה אחת: מ-notes ל-playground, ומשם ל-projects. משם יורדים ל-my-agent. גם cd ~\projects\my-agent הוא פתרון תקין למשימה 5.

2להרוס ולבנות מחדש

uv sync קרא את uv.lock, שבו רשומה הגרסה המדויקת של כל חבילה, והתקין בדיוק אותן. לכן הסביבה החדשה זהה לקודמת.

אילו מחקתם גם את uv.lock, הפקודה uv sync הייתה יוצרת אותו מחדש מתוך pyproject.toml. שם רשום רק "מגרסה 2.10.0 ומעלה", ולכן uv היה בוחר את הגרסאות החדשות ביותר שקיימות באותו יום. היום התוצאה הייתה זהה. בעוד חצי שנה, אחרי שיצאו גרסאות חדשות, הייתם מקבלים סביבה שונה מזו של מי שבנה אותה היום. זו הסיבה שמשתפים את ה-lock file.

3משתנה סביבה משלכם

chat.py

MOCK = os.getenv("CHAT_MOCK", "0") == "1"
AGENT_NAME = os.getenv("AGENT_NAME", "agent")

...

        print(f"{AGENT_NAME}> {reply}\n")
.env.example
# The name printed before each reply
AGENT_NAME=agent

למה לעדכן את .env.example: הקובץ .env שלכם לא משותף. מי שיקבל את הפרויקט לא יידע שהמשתנה קיים אלא אם הוא מופיע בתבנית. כל משתנה חדש שהקוד קורא נרשם שם.

מי ניצח: הערך מה-terminal. load_dotenv() אינו דורס משתנה שכבר קיים בסביבה. זו בחירה מכוונת: הקובץ .env נותן ערכי ברירת מחדל למחשב שלכם, ומי שמריץ את התוכנית יכול לגבור עליהם בלי לערוך קבצים. בשרת אמיתי אין בכלל קובץ .env, והמערכת שמריצה את התוכנית מגדירה את המשתנים ישירות.

4להוסיף חבילה

chat.py
from dotenv import load_dotenv
from rich.console import Console

...

SYSTEM_PROMPT = "You are a friendly assistant. Keep your answers short."

console = Console()

...

        console.print(f"{AGENT_NAME}> {reply}\n", style="cyan", markup=False)

הותקנו ארבע חבילות: rich עצמה, ושלוש שהיא צריכה כדי לעבוד (markdown-it-py, mdurl, pygments). אלה ה-transitive dependencies שלה.

  • ב-pyproject.toml נוספה שורה אחת, "rich>=15.0.0". רשומות בו רק החבילות שאתם ביקשתם.
  • ב-uv.lock נוספו ארבעתן, כל אחת עם הגרסה המדויקת שלה.

הפרמטר markup=False נחוץ כי rich מפרש סוגריים מרובעים כהוראות עיצוב, והתשובות במצב mock מתחילות בסוגריים מרובעים.

5ציד באגים עם ה-debugger

ב-breakpoint רואים ש-messages מכיל 10 איברים וש-max_turns שווה 3. ב-Debug Console, הביטוי messages[-max_turns:] מחזיר 3 איברים בלבד.

הבאג: תור אחד הוא שתי הודעות, אחת של user ואחת של assistant. התנאי בשורה הראשונה של הפונקציה זוכר את זה (max_turns * 2), אבל ה-return שוכח וחותך לפי מספר התורות.

debug_me.py
    return messages[-max_turns * 2:]

למה זה מסוכן: חיתוך של מספר אי-זוגי של הודעות משאיר רשימה שמתחילה בתשובה של assistant, בלי השאלה שקדמה לה. ה-API דורש שההודעה הראשונה תהיה של user, ולכן הבקשה הבאה הייתה נדחית בשגיאה. והבאג היה מתגלה רק בשיחה ארוכה מספיק, כלומר אצל משתמש אמיתי ולא אצלכם בבדיקה קצרה. בפרק 3 תלמדו לכתוב בדיקה אוטומטית שתופסת באג כזה.

6מבחן החבר

אין פתרון יחיד. דוגמה ל-README.md נמצאת בתיקייה checkpoints\chapter-01. הדברים שנשכחים בדרך כלל בניסיון הראשון:

  • הצעד cp .env.example .env. בלעדיו התוכנית עוצרת עם ANTHROPIC_API_KEY is not set.
  • הדרישה ש-uv יהיה מותקן, והקישור להתקנה שלו.
  • ההסבר שאפשר לרוץ בלי מפתח, במצב mock.
  • שכחתם להעתיק את uv.lock לתיקיית הבדיקה. הפרויקט עדיין רץ, אבל כבר לא מובטח שעם אותן גרסאות.

הקבצים שצריך להעתיק: chat.py, debug_me.py, pyproject.toml, uv.lock, .env.example ו-README.md. שתי פקודות מביאות את החבר לשיחה ראשונה: uv sync ואז uv run python chat.py, אחרי יצירת .env.
