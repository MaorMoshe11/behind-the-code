נוספו שני commits: השינוי הגרוע, וה-revert שמבטל אותו. הקוד חזר למצב שלפני, אבל ההיסטוריה לא נמחקה. היא מספרת מה קרה. כך מי שכבר קיבל את a1590bc יקבל עכשיו גם את התיקון, וההיסטוריות לא סותרות.

6מחזור מלא ב-GitHub

אין פתרון יחיד. כמה דברים שכדאי שתבחינו בהם:

  • אפשרות ה-merge: כל אחת לגיטימית אם יש לה סיבה. Squash and merge מתאים כשה-commits בענף הם "ניסיון", "תיקון", "עוד תיקון", ומה שחשוב ב-main הוא commit אחד מסודר. Create a merge commit שומר את כל הצעדים. מה שחשוב הוא לבחור אחת ולכתוב אותה ב-CONTRIBUTING.md.
  • אישור עצמי: GitHub לא מאפשר למי שפתח pull request לאשר אותו. אפשר להעיר (Comment), אבל Approve שמור לאדם אחר. זה בדיוק הרעיון: עוד זוג עיניים.
  • Branch protection: בחשבון חינמי, אכיפה של כללים על main זמינה ל-repositories ציבוריים. ב-repository פרטי בחשבון חינמי תגלו שהכללים לא נאכפים, או שהממשק מציין שהם דורשים תוכנית בתשלום. זה תקין, ולא טעות שלכם.
  • מה היה שונה מה-remote המקומי: פקודות git זהות לחלוטין. מה שנוסף הוא שכבה של אנשים: מקום לתאר את השינוי, לדון בשורות ספציפיות, לאשר, ולתעד את ההחלטה. וההתחברות הראשונה דרך הדפדפן.
  • מעכשיו: אם תמשיכו לעבוד מול GitHub, ה--u ב-git push -u github main קבע ש-git push ו-git pull על main הולכים ל-GitHub. בפרק 9 תצטרכו את ה-repository ב-GitHub, כדי להריץ עליו בדיקות אוטומטיות.
