brief 1: /history shows the title
Goal: in the terminal chat, /history prints the conversation's title as well as the
number of turns, for example: "Plan a trip" - 2 turns saved in this conversation.

Context:
- The command is handled in chat_loop in agent/cli.py; the title comes from
  Conversations.title() in agent/conversations.py.
- Before the first message the title is "New conversation" (NEW_TITLE).
- tests/test_cli.py::test_history_counts_turns_not_messages checks the current text.

Constraints: change only agent/cli.py, tests/test_cli.py and CHANGELOG.md. Keep the
words "N turns saved in this conversation." exactly: the existing test must still pass
unchanged. No change to the HTTP API.

Done means: /history before any message shows "New conversation" and 0 turns; after one
message, the first message's start and 1 turn. A test for both.

Verify: uv run ruff check; uv run ruff format --check;
uv run mypy agent scripts worker pipelines; uv run pytest -q. Paste the last lines.

Out of scope: the web page, /reset, titles in GET /conversations.

both lock files at the newest versions their pyproject.toml allows.

`uv lock --upgrade` in each project. No edits to pyproject.toml, no code changes,
no new packages, no change of Python version. If a check fails after the upgrade,
do not fix the code: stop and tell me which package and which test.

Done means: in both projects, `uv sync --locked`, ruff, mypy, pytest and
`uv audit --locked --preview-features audit` are green.

Verify: paste the output of each command above, and a list of the packages that
changed version (old -> new).

Out of scope: major-version upgrades that need pyproject.toml changes: list them only.

Goal: find out what "slow" means here and where it comes from. Do not change code.

Context:
- The chat calls the notes service through agent/notes.py: NOTES_TIMEOUT (2 s by

- docs/runbook.md, section NotesFailing; the metrics notes_calls_total and

Done means: a short written report: the worst case wait for one /note call (with the

Out of scope: any change to code, config or compose files.

AGENTS.md
# AGENTS.md

A chat agent on the Claude API: CLI, FastAPI service, notes service. Python 3.13, uv.
Always work in mock mode: `$env:CHAT_MOCK = "1"`. No API key is needed or allowed.

## Commands (PowerShell, from the project root)

- Setup: `uv sync --locked`
- All checks, as CI runs them: `uv run ruff check`, `uv run ruff format --check`,
  `uv run mypy agent scripts worker pipelines`, `uv run pytest -q`
- Notes service: the same inside `notes-service/`, with `uv run mypy notes`
- Without Postgres, 4 migration tests are skipped. That is expected.

## Layout

- `agent/`: the chat service (api.py endpoints, conversations.py core, security.py keys and limits)
- `notes-service/`: a separate project with its own pyproject and uv.lock
- `worker/`, `pipelines/`: Kafka consumer, usage report
- `migrations/versions/`: Alembic; `tests/`: pytest; `docs/`: architecture, runbook, security

## Conventions

- One branch per task from `main`: `feature/`, `fix/`, `docs/`. Never commit to `main`.
- A bug fix comes with a test that fails before it. Add a line under "Unreleased" in CHANGELOG.md.
- Every client sees only its own conversations (`own()`, `user_id=caller`). Keep it that way.

## Ask before you

- change or delete an existing test (if one fails, stop and explain why)
- add a dependency (`uv add`), or touch `uv.lock` other than through uv
- change `agent/config.py` defaults, `deploy/`, `.github/workflows/`, `Dockerfile`
- edit a migration in `migrations/versions/` (they may have run already: add a new one)
- run `git push`, `git merge`, `docker compose down -v`, or anything that deletes files

## Never

- read or print `.env` or `deploy/secrets/`; never write a key into any file
- run `scripts/deploy.py`

5ההרשאות של הסוכן

הרשימות של 17.10, מורחבות לכל הפרויקט: מותר בלי לשאול לקרוא את agent\, tests\, docs\, scripts\, migrations\, ולהריץ git status, git diff, git log, uv sync --locked, ruff, mypy, pytest. באישור: uv add, uv lock, git commit, git switch, docker compose up, alembic upgrade על בסיס הנתונים המקומי, כל גישה לרשת. לא בכלל: .env, deploy\secrets\, git push, git reset --hard, docker compose down -v, alembic downgrade, scripts\deploy.py, scripts\make_secrets.py, מחיקת קבצים.

שלוש המסוכנות ביותר: scripts\deploy.py prod (משנה מה שמשתמשים אמיתיים מקבלים), docker compose down -v (מוחק את כל השיחות בלי דרך חזרה), ו-git push (מוציא קוד, ואולי סוד, מהמחשב, ולא ניתן לבטל באמת).

מה אי אפשר לאכוף בהגדרות: כל פקודה מותרת שמריצה קוד היא דלת. אם uv run pytest מותר, סוכן יכול לכתוב בדיקה שקוראת את .env ומדפיסה אותו, וההגדרה "לא לקרוא את .env" לא תעצור את זה. לכן נשארים תלויים בכם שלושה דברים: לקרוא את ה-diff לפני שמריצים קוד חדש, לעבוד בארגז חול שאין בו סודות אמיתיים (מצב mock, .env בלי מפתח), ולא לאשר בעיניים עצומות.

6משימה אמיתית אחת, עם יומן

אין פתרון יחיד. מה שחוזר אצל רוב מי שעושים את התרגיל לראשונה:

  • התדריך הראשון חסר את ה"גמור". המשימה בוצעה, אבל לא הייתה דרך לדעת אם היא מה שרציתם, עד שקראתם את הקוד.
  • רוב התיקונים היו על היקף, לא על נכונות: "לא ביקשתי לשנות גם את X". רשימת קבצים מותרים בתדריך הבא חוסכת את רובם.
  • הדוח היה מדויק פחות מהקוד. קוד אפשר להריץ; דוח רק לקרוא. מכאן הכלל של 17.8.
  • הזמן התחלק אחרת ממה שציפיתם: כתיבת הקוד קצרה מאוד, התדריך וה-review לוקחים את רוב הזמן. זה לא כישלון, זה המקום שבו העבודה שלכם נמצאת עכשיו.
  • מי שעשה את התרגיל בלי כלי, כ"סוכן" של עצמו, מגלה בדיוק את אותם חורים: כל מקום שבו נאלצתם לנחש הוא שורה שחסרה בתדריך.
