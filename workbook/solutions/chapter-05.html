1סיור ב-Swagger

אחרי Authorize, כל בקשה ל-endpoint עם מנעול נשלחת עם X-API-Key והערך שהזנתם. פקודת ה-curl ש-Swagger מציג כוללת אותו, ואת Content-Type: application/json. היא כתובה בסגנון של Linux, עם מירכאות בודדות, ולכן לא תעבוד כמו שהיא ב-PowerShell 5.1 (פרק 4, תרגיל 5).

ב-ChatRequest מופיעים minLength: 1 ו-maxLength: 4000 על message, ו-message ברשימת השדות החובה. הם הגיעו מ-Field(min_length=1, max_length=4000): אותה שורה גם בודקת את הקלט וגם מתעדת אותו. ליד conversation_id מופיע התיאור מ-description.

59 passed. 204 אומר "הצלחתי, ואין מה להחזיר", ולכן ה-body ריק. המחיקה השנייה מחזירה 404, וזה לא סותר idempotency. Idempotency עוסקת במצב שנשאר בשרת, לא בתשובה: אחרי מחיקה אחת או אחרי עשר, השיחה לא קיימת. לקוח שמנסה שוב מחיקה שה-timeout שלה פג יכול להתייחס ל-404 כאל הצלחה. יש APIs שמחזירים 204 גם בפעם השנייה, כדי לחסוך ללקוח את ההבחנה. שתי הבחירות לגיטימיות, בתנאי שהן כתובות בחוזה.

5scripts\ask.py

scripts\ask.py
"""Ask the agent's HTTP API one question, from another program.

Run it with: uv run python scripts/ask.py "your message" [--conversation ID]

It reads AGENT_API_KEY (and AGENT_URL, default http://127.0.0.1:8000) from the
environment or from .env, like the server does.
"""

import argparse
import json
import os
import sys
import urllib.error
import urllib.request

from dotenv import load_dotenv


def ask(url: str, key: str, message: str, conversation_id: str | None) -> dict[str, object]:
    """POST /chat and return the JSON reply. Raises urllib errors on failure."""
    body = json.dumps({"message": message, "conversation_id": conversation_id})
    request = urllib.request.Request(
        f"{url}/chat",
        data=body.encode("utf-8"),
        headers={"Content-Type": "application/json", "X-API-Key": key},
        method="POST",
    )
    # Always a timeout: without one, a server that never answers blocks us forever.
    with urllib.request.urlopen(request, timeout=30) as response:
        reply: dict[str, object] = json.load(response)
        return reply


def main() -> None:
    load_dotenv()
    parser = argparse.ArgumentParser(description="Send one message to the agent's API.")
    parser.add_argument("message")
    parser.add_argument("--conversation", help="continue this conversation id")
    args = parser.parse_args()

    url = os.getenv("AGENT_URL", "http://127.0.0.1:8000")
    key = os.getenv("AGENT_API_KEY")
    if not key:
        sys.exit("AGENT_API_KEY is not set.")

    try:
        data = ask(url, key, args.message, args.conversation)
    except urllib.error.HTTPError as error:
        # The server answered, with an error status (4xx or 5xx). Its body says why.
        detail = json.load(error).get("detail")
        sys.exit(f"The API answered {error.code}: {detail}")
    except urllib.error.URLError as error:
        # No answer at all: DNS or connection failed (chapter 4).
        sys.exit(f"Could not reach {url}: {error.reason}")

    print(data["reply"])
    print(f"(conversation {data['conversation_id']}, turns: {data['turns']})")


if __name__ == "__main__":
    main()

פתרון אפשרי אחד. ב-chat.html, החלק העליון של ה-<script>:

agent\static\chat.html (the new top of the script)
  // The conversation id is kept in sessionStorage, so a page reload continues the same chat.
  let conversationId = null;
  const keyInput = document.getElementById("key");
  try {
    keyInput.value = localStorage.getItem("agent-key") || "";
    conversationId = sessionStorage.getItem("conversation-id");
  } catch (e) { /* no storage: every reload starts a new chat */ }

  function remember(id) {
    conversationId = id;
    try {
      if (id) sessionStorage.setItem("conversation-id", id);
      else sessionStorage.removeItem("conversation-id");
    } catch (e) { /* no storage */ }
  }

  function lost() {
    // 404: the server no longer knows this conversation. In memory, a restart loses everything.
    remember(null);
    show("השיחה הקודמת אבדה, כנראה כי השרת הופעל מחדש. ההודעה הבאה תפתח שיחה חדשה.", "error");
  }

  async function loadHistory() {
    if (!conversationId) return;
    try {
      const response = await fetch("/conversations/" + conversationId, {
        headers: { "X-API-Key": keyInput.value },
      });
      if (response.status === 404) return lost();
      if (!response.ok) return;
      const data = await response.json();
      for (const m of data.messages) show(m.content, m.role === "user" ? "user" : "agent");
    } catch (e) { /* server down: the first send will say so */ }
  }

ובטיפול בתשובה של POST /chat: remember(data.conversation_id) במקום ההשמה, ענף else if (response.status === 404) { lost(); } לפני השגיאה הכללית, ו-loadHistory(); בסוף הסקריפט. sessionStorage שייך ללשונית: רענון ממשיך את השיחה, לשונית חדשה מתחילה שיחה חדשה. זה מה שרוצים כאן. ה-try סביב כל גישה לאחסון קיים כי בחלון פרטי, או כשהאחסון חסום, הגישה זורקת חריגה, והדף צריך לעבוד גם אז.

בדקנו בדפדפן: שתי הודעות, רענון, ושתיהן חזרו עם התשובות, כי בשרת נרשם GET /conversations/... 200. ואחרי הפעלה מחדש של השרת, רענון הציג את הודעת "השיחה הקודמת אבדה" (GET /conversations/... 404).

מה הדף לא יכול להציל: את השיחה עצמה. הדף זוכר רק מזהה. ההודעות נמצאות בשרת, ובזיכרון שלו בלבד, ולכן הפעלה מחדש מוחקת אותן ואין מאיפה להחזיר. וגם כשהשרת חי, GET מחזיר רק את מה שהליבה עוד זוכרת, כלומר את CHAT_MAX_TURNS התורות האחרונים: הקיצוץ מפרק 3 מוחק את השאר לתמיד. הפתרון הוא לשמור כל הודעה, כשהיא נוצרת, במקום שחי מחוץ לתהליך: בסיס נתונים, עם טבלת שיחות (המזהה, מתי נוצרה) וטבלת הודעות (לאיזו שיחה, תפקיד, תוכן, מתי). מה שנשלח למודל יכול עדיין להיות מקוצץ, אבל מה שנשמר הוא הכול. זה פרק 6.
